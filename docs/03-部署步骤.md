## 步骤 1 · 把代码放进 GitHub 仓库

**Windows**：打开「开始菜单 → 搜索 PowerShell → 回车」，在打开的窗口里执行：

```powershell
cd "$HOME\Documents"
mkdir mistake-notebook-repo
cd mistake-notebook-repo
git init
```

**Mac**：打开「启动台 → 其他 → 终端」，执行：

```bash
cd ~/Documents
mkdir mistake-notebook-repo && cd mistake-notebook-repo
git init
```

把本项目 `mistake-notebook/` 目录里的**所有文件**复制进这个文件夹（包括 `.env.example`，但**不要**复制 `.env.local`）。然后：

```bash
git add .
git commit -m "init: 错题本网站"
git branch -M main
git remote add origin https://github.com/你的用户名/mistake-notebook.git
git push -u origin main
```

**预期输出**：`Enumerating objects: ..., done.` … `To https://github.com/...` … `* [new branch] main -> main`。
**易错提醒**：如果提示 `Author identity unknown`，先执行 `git config --global user.email "你的邮箱"` 和 `git config --global user.name "你的名字"`。

> 没有 GitHub 账号？去 https://github.com 注册 → 右上角 `+` → `New repository` → 名字填 `mistake-notebook` → **不要**勾选 README/LICENSE → Create repository，然后按页面提示拿到仓库地址。

## 步骤 2 · 创建 Supabase 项目并执行 SQL

1. 打开 https://supabase.com → `Start your project` → 用 GitHub 登录。
   - **首次登录会先看到 `Your organizations` 空列表页**：点绿色 `New organization` → Name 填 `personal`、Type 选 `Personal`、Plan 选 **`Free - $0/month`** → `Create organization`。组织只是装项目的容器，个人用也必须建一个、不额外收费、不用邀请任何人；建好后才会出现 `New project` 按钮。详见 `05-使用与维护手册.md` 阶段 B 第 7.5 步。
2. `New project`：Name 填 `mistake-notebook`，Database Password **自己设一个并记下来**，点开 Region 下拉**直接选** `Southeast Asia (Singapore) ap-southeast-1`（或 `Northeast Asia (Tokyo) ap-northeast-1`），别用默认 `Auto`（可能分到美国，建好后不能改）。新版界面在同一个下拉里列出 `RECOMMENDATION` / `GENERAL REGIONS` / `SPECIFIC REGIONS`，**没有** `Need a specific region?` 这个链接，别再找它。点 `Create new project`，等 2 分钟。
   - 表单下方 Security 区：`Enable Data API` **保持勾选**（关掉则 `supabase-js` 全挂）、`Automatically expose new tables` **建议保持勾选**、`Enable automatic RLS` 可不勾（`schema.sql` 自己会逐表开 RLS）。详见 `05-使用与维护手册.md` 第 8 步说明；`schema.sql` 的 IV.10b 已补齐显式 `GRANT`。
3. 左侧 **SQL Editor** → `New query` → 把 `supabase/schema.sql` **全文**粘贴 → 点 `Run`。若弹出 `Potential issues detected`（destructive operations / creates tables without RLS 两条**静态扫描提示**），**点橙色 `Run without RLS`**：脚本自带 31 张表的 RLS 与 `own_rows` 策略，这个按钮不是关掉 RLS，只是不让平台重复补刀；详见 `05-使用与维护手册.md` 第 10 步。
   - **预期输出**：`Success. No rows returned`
4. 自检（再开一个 query，**只跑这一条**）：

```sql
select
  (select count(*) from pg_tables where schemaname='public') as tables_total,
  (select count(*) from pg_tables where schemaname='public' and rowsecurity) as rls_true,
  (select count(*) from pg_policies where schemaname='storage' and tablename='objects' and policyname like 'img_%') as img_policies,
  (select public from storage.buckets where id='mistake-images') as bucket_public;
```

   - **预期输出**：一行 `31 | 31 | 4 | false`（31 张表全开 RLS、4 条图片策略齐全、私有桶）。早期版本写「16 行」是 v1 口径。
   - ⚠️ 新版 SQL Editor 的 `Results` 面板**只显示最后一条语句的结果**，别把两句 select 放一起跑，否则只看得到最后一句、误以为表没建。详见 `05-使用与维护手册.md` 第 11 步。
5. 左侧 **Authentication** → `CONFIGURATION` 分组 → **`Sign In / Providers`**（旧版叫 `Providers`）→ `Email`：确认启用，个人使用建议把 `Confirm email` **关掉**（否则每次注册都要去邮箱点确认）。默认落在 `Users` 页显示 `No users in your project` 是正常的，不用管。
6. **Authentication → URL Configuration**：
   - `Site URL`：`http://localhost:3000`（部署后改成 Vercel 域名）
   - `Redirect URLs` → `Add URL`：加 `http://localhost:3000/api/auth/callback` 和 `https://你的项目.vercel.app/api/auth/callback`
7. **Project Settings（齿轮）→ `CONFIGURATION` → `API Keys`**（旧版叫 `Settings → API`）抄下 3 个值：
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - 公开 key：`anon public`（新版 `Publishable key` / `sb_publishable_...`）→ `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - 保密 key：`service_role secret`（新版 `Secret key` / `sb_secret_...`）→ `SUPABASE_SERVICE_ROLE_KEY`（**保密，只读分享要用**）
   - 两套 key 同时有效、可混用：老版 `anon`+`service_role`（`eyJ...`）或新版 `Publishable key`+`Secret key`（`sb_publishable_`/`sb_secret_`）。官方迁移文档确认 `createClient` 可直接替换，本项目静态核证兼容（SDK 2.119.0、无 Edge Functions / pg_net）；**未做真实库联调**。变量名不变，详见 `05-使用与维护手册.md` 第 12 步。若部署后报 `Invalid JWT` / 401，改回 `Legacy API keys` 两串并 Redeploy。
   - `Project URL` 是建项目时自动分配的 `https://<随机项目ref>.supabase.co`（**不是** `supabase.com/dashboard/...`，也不是 `*.vercel.app`）；找不到就点项目页的 `Connect` 按钮，或用地址栏里的项目 ref 自己拼。这个值不保密，另两串 key 保密。

> ⚠️ Supabase 免费项目**连续 7 天无访问会自动暂停**。每周打开一次网站即可；暂停后到控制台点 `Restore project` 唤醒（约 1 分钟）。

## 步骤 4 · Vercel 部署，拿到公网网址

1. 打开 https://vercel.com → `Sign Up` → `Continue with GitHub`，用同一个 GitHub 账号登录。若弹出 `Choose a Plan`：**点第二项 `I'm working on personal projects`（`Hobby`，$0/月）**，别保留默认的 `commercial projects / Pro`（那行 `Pro plan trial with $20 in credit` 是付费试用）；`Team Name` 随便填一个（如 `personal`），确认不再出现 Pro trial 字样再 `Continue`。要信用卡就停下，详见 `05-使用与维护手册.md` 第 13 步。
2. 新版首页 `Start Building with Vercel` → `Import Git Repository` 区块 → 点黑色 **`GitHub`** 按钮（旧版是 `Add New… → Project`）→ 授权 GitHub App（建议 `Only select repositories` 只勾 `mistake-notebook`）→ 列表里选 `mistake-notebook` → `Import`。别点右上角 `Collaborate on a Pro Trial`、`Clone Template` 模板或顶部 v0 输入框。**进配置页先别点黑色 `Create Project`**，先按第 4 步填环境变量。
3. 配置页确认 `Application Preset: Next.js`、`Root Directory: ./`、`Vercel Team` 下拉带 `Hobby` 徽章。展开 `Build and Output Settings` 会看到 Build Command / Output Directory / Install Command 三行灰色占位文字，**全部保持默认，右侧铅笔一个都别点**。
4. 展开 **Environment Variables**：新版是一组单行 `Key` / `Value` 输入框（不是表格），替换掉灰色 `EXAMPLE_NAME` → 填值 → `+ Add More` 加下一行，共 3 行：

| Key | Value | 保密 | 必需 |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co` | 否 | ✅ |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key | 否 | ✅ |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role secret | **是** | ✅ |
| `NEXT_PUBLIC_SITE_URL` | 拿到真实域名后再补 | 否 | ⭕ 首次可不填 |

> `Environments` 下拉保持默认 `Production and Preview`。**别用 `Import .env`** 粘 `.env.example`（会带进注释和空 AI 变量）。`NEXT_PUBLIC_SITE_URL` 首次不填不会白屏：登录页用 `window.location.origin`、分享接口用 `new URL(req.url).origin` 回退；部署后按第 7 步补真实域名并 `Redeploy`。

5. 点 **`Create Project`** → 下方 `Optional Integrations` 卡片里 **`Supabase / Postgres backend` 的 `Add` 不要点**（Marketplace 集成会另建资源、变量名对不上）→ `Deploy` 由灰变可点后点它 → 等待 1–3 分钟 → 出现大字 **`Deployed to Production`** + `You deployed a new project to <团队名> in 1 minute.` + **`Visit`** 按钮（新版**没有** `Congratulations` 字样，认准前者即可）。成功页的 `Add Domain` / `Enable Speed Insights` / `Onboard your agent` 都不用点。若 `Deploy` 一直灰，刷新或到 `Deployments → Create Deployment`。**部署成功只代表编译通过，登录/上传/分享仍需第 7 步之后实测。**
   - **预期输出**：构建日志末尾 `✓ Compiled successfully`、`Build Completed`。
6. 复制公网网址，例如 `https://mistake-notebook-xxx.vercel.app`。
7. 回到 Supabase → `Authentication → URL Configuration`（**最关键，漏了登录会跳回 localhost:3000**）：`Site URL` 填**网站根地址** `https://你的域名`（⚠️ **不要带 `/api/auth/callback`**，那是回调路径，只属于下面的 Redirect URLs）→ 点该卡片右下角绿色 **`Save changes`**；`Redirect URLs → Add URL` 加上 `https://你的域名/api/auth/callback`（原来的 localhost 那条留着，加完 `Total URLs: 2`）。导航易错：若左侧是 `General / Infrastructure / API Keys / JWT Keys / Log Drains`，说明你还在 `Project Settings` 的同名 `CONFIGURATION` 分组里，要先点左上角项目名回主界面、再点钥匙图标 `Authentication`（或用 `Ctrl + K` 搜 `URL Configuration`）。同时把 Vercel 的 `NEXT_PUBLIC_SITE_URL` 新增/改成这个网址：`Settings → Environment Variables` 列表页右上黑色 **`Add Environment Variable`**（改已有行用行尾 `... → Edit`，列表不显示值）→ 弹窗里 **Type 务必选 `Config`**（默认是 `Secret`，保存后不能查看值、不能改 Key、也不能原地转 Config，只能删了重建；`NEXT_PUBLIC_` 本来就内联进前端、是公开值）→ `Environments` 点开下拉勾 `Production + Preview`（默认只有 `Production`）→ `Save`，再回项目页顶部 `Deployments → … → Redeploy`（弹窗标题新版就叫 `Redeploy`，`Use existing Build Cache` 默认未勾选、保持不勾；其余选项全默认，只点右下黑色 `Redeploy`；**成功判定**：列表**新增一条**部署，中间列显示 `Redeploy of <部署ID>`（**不是 commit hash、也不显示 `main`**；`57571cd` + `main` 只在旧条目上）、时间 `Just now`、先 `Building` 后 `Ready`；只看到旧条目就 `F5` 刷新或重做，点过按钮不等于生效）。`Note` / `+ Add new variable` / `Import .env` 都别碰。

## 步骤 5 · （可选）配置阿里云百炼 Coding Plan

**不配置也能用**：设置页会显示「AI未配置」，AI 入口自动禁用，手动录题/图片/复习/打印/统计全部正常。

要用 AI 时：

1. 打开阿里云百炼控制台 → 订阅 **Coding Plan** 套餐 → 在 Coding Plan 页面获取 **专属 API Key**（`sk-sp-` 开头）。
2. Vercel → `Settings → Environment Variables` 添加：

| Name | Value |
| --- | --- |
| `AI_BASE_URL` | `https://coding.dashscope.aliyuncs.com/v1` |
| `DASHSCOPE_CODING_API_KEY` | `sk-sp-你的专属Key`（**保密**） |
| `AI_MODEL` | `qwen3.7-plus` |
| `VISION_MODEL` | `qwen3.7-plus` |
| `OCR_MODEL` | `qwen3.7-plus` |

3. `Deployments → … → Redeploy`（改环境变量后必须重新部署一次）。
4. 登录网站 → `/settings` → 打开「启用AI功能」总开关 → 页面显示 `AI功能当前状态：已开启` 与模型名。
5. 到任意错题详情点「AI整理」，应返回结构化预览。

> **千万不要**填普通按量计费的 `sk-` Key，也不要把 Base URL 写成 `dashscope.aliyuncs.com/compatible-mode/v1` 或含 `maas.aliyuncs.com` 的地址 —— Coding Plan 与通用接口不互通，会鉴权失败或产生额外按量扣费。详见手册第 3 部分排错表。

## 常见部署故障速查

| 现象 | 排查 |
| --- | --- |
| 部署后打开是 404 / 一直跳登录 | 优先查 Supabase `Authentication → URL Configuration` 是否还写着 `http://localhost:3000`（最常见）；再查 `NEXT_PUBLIC_SITE_URL` 与 `Site URL` / `Redirect URLs` 是否一致；改完重新部署 |
| 登录报 `Invalid login credentials` | Email Provider 未启用，或开启了 `Confirm email` 但没去邮箱确认 |
| 页面白屏/接口 500 | Vercel → Project → Logs 查看；多半是环境变量漏填（尤其 `SUPABASE_SERVICE_ROLE_KEY`） |
| 图片上传失败 | 检查 `schema.sql` 是否完整执行、Storage 桶 `mistake-images` 是否存在、路径首段是否为用户 id |
| SQL Editor 报 `42501: must be owner of table objects` | 粘的是旧版 `schema.sql`（含 `comment on table storage.objects`，`postgres` 不是该表 owner）。换最新版整份重跑（幂等）；仍失败见 `05-使用与维护手册.md` 第 10 步的探针与图形界面兜底 |
| 图片不显示 | 私有桶必须走签名 URL；1 小时后签名过期，刷新页面会重新签名 |
| AI 一直显示「AI未配置」 | 环境变量没填或改完没 Redeploy；到设置页看 `configIssues` 具体缺什么 |
| 免费版网站突然打不开 | Supabase 项目 7 天无访问被暂停，去控制台 Restore |

# v2 增量部署说明（第 7 段）

## V1. 已经部署过 v1 的人，怎么升级（不用重建项目）

1. **数据库**：Supabase → SQL Editor → New query → 把当前仓库的 `supabase/schema.sql` **整份**全选粘贴 → Run。
   - 文件是幂等的：`create table if not exists` / `add column if not exists` / `drop policy if exists` 都不会破坏已有错题。
   - 会新建 13 张表、给 `user_settings` 加 9 列、放宽 `ai_jobs.kind` 与 `share_links.scope` 约束、重建统一回收站函数与触发器。
   - 预期输出：`Success. No rows returned`。
2. **自检**：执行下面 3 条，确认升级成功。

```sql
-- 期望 30 行、rls 全为 true
select tablename, rowsecurity as rls from pg_tables where schemaname='public' order by tablename;
```

```sql
-- 期望包含 ai_schedule_parse / ai_note_summary / ai_plan
select column_name from information_schema.columns
 where table_schema='public' and table_name='user_settings' and column_name like 'ai_%' order by 1;
```

```sql
-- 期望返回 []（或你已删除的条目）
select public.unified_trash();
```

3. **代码**：把更新后的代码 `git add . && git commit -m "v2 个人综合管理" && git push`，Vercel 会自动重新部署。
4. **环境变量**：**一个都不用改**。Coding Plan 的 `DASHSCOPE_CODING_API_KEY`、`AI_BASE_URL`、`AI_MODEL/VISION_MODEL/OCR_MODEL` 保持原值；新增的 AI 日程解析 / 笔记总结走同样的文本模型。
5. **开关**：登录后到 `/settings` 会看到 7 个子开关（原 4 个 + AI日程解析 + AI笔记总结 + AI规划）。**总开关不会被升级重置**，原本关闭就仍然关闭 —— 这保证升级过程零 AI 费用。想用新功能再单独打开。
6. **验证新增模块**：见 `04-验收清单.md` 的「V. v2 追加验收（12 条）」。

## V5.3 本地 OCR 的网络要求（唯一新增的外部依赖）

- 识别本身**完全在浏览器 Worker 里跑**：图片不上传、不调用 `/api/ai/*`、AI 总开关关闭时照常可用、零费用。
- 但**首次使用**要从公共 CDN 下载 Tesseract WASM 引擎与语言包（引擎约 3–5MB，中文+英文约 16MB）。下载的是程序/字典文件，不是用户图片。
- 下载后写入浏览器 IndexedDB / Cache Storage，之后可离线识别；清浏览器数据、换设备、换浏览器会重新下载。
- 若网络完全隔离公网 CDN，会卡在「正在下载语言包」并在 120 秒后超时提示；此时**不影响手动录题**（原图保留）。彻底内网使用需要自托管语言包，本次未实现。
- 语言包默认只加载「简体中文 + 英文」，其他语言在 `/settings` 按需勾选，每多一种约 4–14MB，只在第一次用那种语言时下载。

## V5.4 已知降级与限制（如实告知）

1. **`.apkg 未实现，已用 CSV/TSV 替代`**。Anki 导出的是一个 zip：`mistakes.tsv`（Tab 分隔，Front/Back 两列）、`mistakes.csv`（逗号分隔备选）、`mistakes.tsv.media/`（PNG/JPEG 图片）、`导入说明.txt`。Anki 桌面版「文件 → 导入」可直接导入，字段映射与图片处理步骤写在手册第六部分，也在 zip 的说明文件里。

| 列表缩略图是空白 | 老数据没有缩略图，会自动回退用大图；重新上传一次即可生成 |
| 整题上传后没有 OCR 文字 | AI 总开关 / OCR 子开关 / Key / Base URL 任一未满足 → 预计调用 0 次，属正常；点「本地 OCR」或手动录入 |
| 孤儿文件扫描列出刚上传的图 | 上传成功但没保存错题（放弃录入）会留下临时文件；勾选确认后清理即可 |
| 清空回收站后手机还能看到图 | 浏览器缓存；刷新或清 PWA 缓存。Storage 文件本身已删除 |

**V6 小结 · 下一步该做什么**：完成 V6.1–V6.5 后，对照 `04-验收清单.md` 的 **VII 段（20 条）**逐项勾选，日常操作看 `05-使用与维护手册.md` **第七部分**。若 `verify-migration.mjs` 有失败项，把终端输出整段发我。

## V7.2 第 1 步 · 执行数据库迁移 SQL（幂等）

> ⚠️ **必做，不能跳**：只要你的库是「跑完 `schema.sql` 建的」（v1~v4 初次部署），库里**只有 31 张表，没有课本模块的表**。不跑这一步，打开 `/textbooks` 会报 `relation "textbooks" does not exist`。**先跑迁移，再部署代码**。

在 Supabase → SQL Editor 新建查询，**整份粘贴 `supabase/migration-textbooks.sql`** → Run → 若弹出 `Potential issues detected` 仍点橙色 `Run without RLS`（脚本自带 6 张表的 RLS 与 `own_rows` 策略）。可以重复执行，不会删改已有数据。

它会做这些事：

| 动作 | 内容 |
| --- | --- |
| 加列 | `user_settings.ai_textbook_quiz`（默认 `false`，跨设备同步） |
| 放宽约束 | `ai_jobs.kind` 追加 `textbook_quiz`；`trash_items.entity_type` 追加 `textbook/chapter/material` |
| 建 6 张表 | 课本 / 章节 / 知识点映射 / 错题映射 / 材料 / 组卷模板 |
| RLS | 6 张表全部启用行级安全 + `own_rows`（`auth.uid() = user_id`） |
| ★ 授权 | 全量 `grant` 给 `authenticated` / `service_role`（不开放 `anon`）。建库那次 grant 覆盖不到后来新建的表，不补会报 `42501 permission denied for table textbooks` |
| Storage | `mistake-images` 桶的 `allowed_mime_types` 追加 `application/pdf`（课本 PDF 片段） |
| 回收站 | 3 类新实体的登记/恢复/彻底删除/过期清理；课本恢复会连带章节与材料 |
| 注销 | `delete_my_data()` 追加清理课本模块数据 |

**预期**：`Success. No rows returned`。然后新建 query 跑迁移文件末尾「10. 执行后自检」的**四合一语句**，预期一行 **`6 | 6 | 1 | 1`**（6 张表 / 6 张开 RLS / 授权到位 / AI 子开关注入）。对不上就把那一行原样发我，别往下走。

> ⚠️ **Storage 桶 MIME 那条可能不生效**：`storage.buckets` 由 `supabase_storage_admin` 拥有，某些项目里 SQL Editor 的 `postgres` 角色执行 `UPDATE` 会报 `42501 must be owner of table buckets`（与 v4 的 `comment on table storage.objects` 同源）。迁移里已用异常保护包住，**失败只给 notice、不会中断整份脚本**，后面的回收站与授权照常执行。此时到 **Storage → `mistake-images` → Configuration → Allowed MIME types** 手动加 `application/pdf` → `Save`。图片上传不受影响，只有 PDF 片段会报 415。
> ⚠️ 若之后又整份重跑 `schema.sql`，请再跑一次本迁移，确保 `ai_jobs.kind`、`trash_items` 约束、桶 MIME 与授权是最新版本。
