## 步骤 1 · 把代码放进 GitHub 仓库

**Windows**：打开「开始菜单 → 搜索 PowerShell → 回车」，在打开的窗口里执行：

```powershell
cd "$HOME\Documents"
mkdir mistake-notebook-repo
cd mistake-notebook-repo
git init
```

**Mac**：打开「启动台 → 其他 → 终端」，执行：

```bash
cd ~/Documents
mkdir mistake-notebook-repo && cd mistake-notebook-repo
git init
```

把本项目 `mistake-notebook/` 目录里的**所有文件**复制进这个文件夹（包括 `.env.example`，但**不要**复制 `.env.local`）。然后：

```bash
git add .
git commit -m "init: 错题本网站"
git branch -M main
git remote add origin https://github.com/你的用户名/mistake-notebook.git
git push -u origin main
```

**预期输出**：`Enumerating objects: ..., done.` … `To https://github.com/...` … `* [new branch] main -> main`。
**易错提醒**：如果提示 `Author identity unknown`，先执行 `git config --global user.email "你的邮箱"` 和 `git config --global user.name "你的名字"`。

> 没有 GitHub 账号？去 https://github.com 注册 → 右上角 `+` → `New repository` → 名字填 `mistake-notebook` → **不要**勾选 README/LICENSE → Create repository，然后按页面提示拿到仓库地址。

## 步骤 2 · 创建 Supabase 项目并执行 SQL

1. 打开 https://supabase.com → `Start your project` → 用 GitHub 登录。
2. `New project`：Name 填 `mistake-notebook`，Database Password **自己设一个并记下来**，Region 选 `Singapore` 或 `Tokyo`（离国内近），点 `Create new project`，等 2 分钟。
3. 左侧 **SQL Editor** → `New query` → 把 `supabase/schema.sql` **全文**粘贴 → 点 `Run`。
   - **预期输出**：`Success. No rows returned`
4. 自检（再开一个 query 粘进去执行）：

```sql
select tablename, rowsecurity as rls from pg_tables where schemaname='public' order by tablename;
select id, public from storage.buckets where id='mistake-images';
```

   - **预期输出**：**31 行**且 `rls` 全部为 `true`（v4 PART I~IV 共 31 张业务表）；第二句 1 行 `mistake-images | false`（`false` = 私有桶，正确）。早期版本写「16 行」是 v1 口径。
5. 左侧 **Authentication** → `Providers` → `Email`：确认启用。个人使用建议把 `Confirm email` **关掉**（否则每次注册都要去邮箱点确认）。
6. **Authentication → URL Configuration**：
   - `Site URL`：`http://localhost:3000`（部署后改成 Vercel 域名）
   - `Redirect URLs` → `Add URL`：加 `http://localhost:3000/api/auth/callback` 和 `https://你的项目.vercel.app/api/auth/callback`
7. **Project Settings → API** 抄下 3 个值：
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role secret` → `SUPABASE_SERVICE_ROLE_KEY`（**保密，只读分享要用**）

> ⚠️ Supabase 免费项目**连续 7 天无访问会自动暂停**。每周打开一次网站即可；暂停后到控制台点 `Restore project` 唤醒（约 1 分钟）。

## 步骤 4 · Vercel 部署，拿到公网网址

1. 打开 https://vercel.com → `Sign Up` → 用同一个 GitHub 账号登录。
2. `Add New… → Project` → `Import Git Repository` → 选 `mistake-notebook` → `Import`。
3. Framework 会自动识别 `Next.js`，**不要改** Build Command / Output Directory。
4. 展开 **Environment Variables**，逐条添加（值后面说明保密性）：

| Name | Value | 保密 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co` | 否 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key | 否 |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role secret | **是** |
| `NEXT_PUBLIC_SITE_URL` | `https://你的项目.vercel.app` | 否 |

> 第一次部署还不知道域名？可以先填 `https://你的项目.vercel.app`（Vercel 会按项目名生成，通常就是 `https://mistake-notebook-xxx.vercel.app`）。部署成功后到 `Settings → Domains` 复制真实域名，再回来改这个变量并 `Redeploy` 一次。

5. 点 `Deploy` → 等待 1–3 分钟 → 出现 `Congratulations!` 和 `Visit` 按钮。
   - **预期输出**：构建日志末尾 `✓ Compiled successfully`、`Build Completed`。
6. 复制公网网址，例如 `https://mistake-notebook-xxx.vercel.app`。
7. 回到 Supabase → `Authentication → URL Configuration`：把 `Site URL` 改成这个网址，Redirect URLs 加上 `https://你的域名/api/auth/callback`。同时把 Vercel 的 `NEXT_PUBLIC_SITE_URL` 改成这个网址并重新部署。

## 步骤 5 · （可选）配置阿里云百炼 Coding Plan

**不配置也能用**：设置页会显示「AI未配置」，AI 入口自动禁用，手动录题/图片/复习/打印/统计全部正常。

1. 打开阿里云百炼控制台 → 订阅 **Coding Plan** 套餐 → 在 Coding Plan 页面获取 **专属 API Key**（`sk-sp-` 开头）。
2. Vercel → `Settings → Environment Variables` 添加：

| Name | Value |
| --- | --- |
| `AI_BASE_URL` | `https://coding.dashscope.aliyuncs.com/v1` |
| `DASHSCOPE_CODING_API_KEY` | `sk-sp-你的专属Key`（**保密**） |
| `AI_MODEL` | `qwen3.7-plus` |
| `VISION_MODEL` | `qwen3.7-plus` |
| `OCR_MODEL` | `qwen3.7-plus` |

3. `Deployments → … → Redeploy`（改环境变量后必须重新部署一次）。

5. 到任意错题详情点「AI整理」，应返回结构化预览。

> **千万不要**填普通按量计费的 `sk-` Key，也不要把 Base URL 写成 `dashscope.aliyuncs.com/compatible-mode/v1` 或含 `maas.aliyuncs.com` 的地址 —— Coding Plan 与通用接口不互通，会鉴权失败或产生额外按量扣费。详见手册第 3 部分排错表。

## 常见部署故障速查

| 现象 | 排查 |
| --- | --- |
| 部署后打开是 404 / 一直跳登录 | `NEXT_PUBLIC_SITE_URL` 与 Supabase `Site URL`、`Redirect URLs` 不一致；改完重新部署 |
| 登录报 `Invalid login credentials` | Email Provider 未启用，或开启了 `Confirm email` 但没去邮箱确认 |
| 页面白屏/接口 500 | Vercel → Project → Logs 查看；多半是环境变量漏填（尤其 `SUPABASE_SERVICE_ROLE_KEY`） |
| 图片上传失败 | 检查 `schema.sql` 是否完整执行、Storage 桶 `mistake-images` 是否存在、路径首段是否为用户 id |
| 图片不显示 | 私有桶必须走签名 URL；1 小时后签名过期，刷新页面会重新签名 |
| AI 一直显示「AI未配置」 | 环境变量没填或改完没 Redeploy；到设置页看 `configIssues` 具体缺什么 |
| 免费版网站突然打不开 | Supabase 项目 7 天无访问被暂停，去控制台 Restore |

# v2 增量部署说明（第 7 段）

## V1. 已经部署过 v1 的人，怎么升级（不用重建项目）

1. **数据库**：Supabase → SQL Editor → New query → 把当前仓库的 `supabase/schema.sql` **整份**全选粘贴 → Run。
   - 文件是幂等的：`create table if not exists` / `add column if not exists` / `drop policy if exists` 都不会破坏已有错题。
   - 会新建 13 张表、给 `user_settings` 加 9 列、放宽 `ai_jobs.kind` 与 `share_links.scope` 约束、重建统一回收站函数与触发器。
   - 预期输出：`Success. No rows returned`。
2. **自检**：执行下面 3 条，确认升级成功。

```sql
-- 期望 30 行、rls 全为 true
select tablename, rowsecurity as rls from pg_tables where schemaname='public' order by tablename;
```

```sql
-- 期望包含 ai_schedule_parse / ai_note_summary / ai_plan
select column_name from information_schema.columns
 where table_schema='public' and table_name='user_settings' and column_name like 'ai_%' order by 1;
```

```sql
-- 期望返回 []（或你已删除的条目）
select public.unified_trash();
```

3. **代码**：把更新后的代码 `git add . && git commit -m "v2 个人综合管理" && git push`，Vercel 会自动重新部署。
4. **环境变量**：**一个都不用改**。Coding Plan 的 `DASHSCOPE_CODING_API_KEY`、`AI_BASE_URL`、`AI_MODEL/VISION_MODEL/OCR_MODEL` 保持原值；新增的 AI 日程解析 / 笔记总结走同样的文本模型。
5. **开关**：登录后到 `/settings` 会看到 7 个子开关（原 4 个 + AI日程解析 + AI笔记总结 + AI规划）。**总开关不会被升级重置**，原本关闭就仍然关闭 —— 这保证升级过程零 AI 费用。想用新功能再单独打开。
6. **验证新增模块**：见 `04-验收清单.md` 的「V. v2 追加验收（12 条）」。

> ⚠️ **易错提醒**：只跑 PART II 那一段会因为找不到 `public.mistakes` 而报错，一定整份执行。
> ⚠️ 若 SQL Editor 报 `constraint ... does not exist`，说明你之前手工改过约束名；把报错的 `drop constraint if exists` 那两行保留即可，它们不会中断执行。

## V2. 全新部署的人，和 v1 只有一处不同

照着本文「步骤 1 → 步骤 N」原样做即可。唯一区别：**第 2 步执行 SQL 时，粘贴的是现在这份包含 PART I + II + III + IV 的完整 `supabase/schema.sql`**，一次建好 31 张表，不需要分两次，也不需要单独跑 PART IV。

## V5.1 改了什么（需要重新部署代码，但不用改环境变量）

| 项目 | 变化 | 你要做什么 |
| --- | --- | --- |
| 依赖 | 新增 `docx`、`jszip`、`tesseract.js`、`sharp` | `npm install` 自动装；Vercel 构建时自动安装，**不用手动加环境变量** |
| 环境变量 | **一个都不用新增、不用修改** | 什么都不用做（本次只是代码变更，推 GitHub 即自动部署） |
| 数据库 | `supabase/schema.sql` 追加 **PART III**（幂等唯一索引 + 重算说明注释） | 老项目在 SQL Editor **整份重跑一次**；不新增表、不删数据。新项目照旧整份执行一次 |
| API 路由 | 新增 `POST /api/export/word`、`POST /api/export/anki` | 二者都用登录用户 session + RLS，且声明 `runtime = 'nodejs'`（sharp / docx 需要 Node 运行时，不能用 Edge） |
| 前端 | 错题详情、错题列表批量条加导出入口；图片上传加本地 OCR 按钮；设置页加 OCR 设置；习惯页加补打卡 | 推代码即可 |

> **sharp 的作用**：站点上传的图片是 WebP，而 Word 的 docx 规范只可靠支持 PNG/JPEG、Anki 对 WebP 的支持取决于客户端。导出时 sharp 会把 WebP 转成 PNG 并读出真实像素尺寸。若服务器缺 sharp，导出仍会成功，但会跳过 WebP 图片并在页面给黄色提示（降级路径见 `lib/export/image.ts`）。

## V5.3 本地 OCR 的网络要求（唯一新增的外部依赖）

- 识别本身**完全在浏览器 Worker 里跑**：图片不上传、不调用 `/api/ai/*`、AI 总开关关闭时照常可用、零费用。
- 但**首次使用**要从公共 CDN 下载 Tesseract WASM 引擎与语言包（引擎约 3–5MB，中文+英文约 16MB）。下载的是程序/字典文件，不是用户图片。
- 下载后写入浏览器 IndexedDB / Cache Storage，之后可离线识别；清浏览器数据、换设备、换浏览器会重新下载。
- 若网络完全隔离公网 CDN，会卡在「正在下载语言包」并在 120 秒后超时提示；此时**不影响手动录题**（原图保留）。彻底内网使用需要自托管语言包，本次未实现。
- 语言包默认只加载「简体中文 + 英文」，其他语言在 `/settings` 按需勾选，每多一种约 4–14MB，只在第一次用那种语言时下载。

## V5.4 已知降级与限制（如实告知）

1. **`.apkg 未实现，已用 CSV/TSV 替代`**。Anki 导出的是一个 zip：`mistakes.tsv`（Tab 分隔，Front/Back 两列）、`mistakes.csv`（逗号分隔备选）、`mistakes.tsv.media/`（PNG/JPEG 图片）、`导入说明.txt`。Anki 桌面版「文件 → 导入」可直接导入，字段映射与图片处理步骤写在手册第六部分，也在 zip 的说明文件里。
2. **Word 是真正的 `.docx`**（不是 HTML 改后缀），图片 Base64 解包后写入 `word/media/`、用 `r:embed` 内嵌，**随文件走、换电脑/断网都不丢图**；公式只保留文本形式（不渲染 KaTeX）。
3. **本地 OCR 只输出纯文本**，不生成 LaTeX 公式，手写体与复杂公式识别较弱；需要精确公式要开 AI OCR 或手动输入。
4. **习惯补录重算范围**：前端重新拉取当前用户全部 `habit_logs`（个人量级一次查询），连续天数最多回溯 730 天；日志超过 5000 行需另建索引，本次未做分页。
5. **导出单次上限 300 道 / 40 张图 / 6MB 图片**，超出会在页面给黄色提示并只导出前 300 道，可缩小筛选范围分批导出。这是 Vercel 函数响应体大小的安全余量。
6. **未真实联调**：没有 Supabase / Vercel / Coding Plan 凭据，也没有在 Word / Anki / 真机浏览器里实际打开过导出文件。逐项验证照 `08-真实联调清单.md` 做。

# V6 · 图片架构 v4 升级与数据迁移（本次增量）

> 改造清单与字段说明见 `09-图片架构v4改造清单.md`；SQL 在 `supabase/schema.sql` 的 **PART IV**。
> **网站运行没有新增任何环境变量**，Vercel 里不用改配置；只有本地一次性迁移脚本需要临时的 `SUPABASE_SERVICE_ROLE_KEY`。

## V6.1 第 1 步 · 升级前先备份（必做）

1. 打开 Supabase → 你的项目 → **Database → Backups**，确认有一次可用备份（免费版保留 7 天点备份，Pro 才有按时间点恢复；免费版请务必继续做第 2 步）。
2. 打开网站 → **设置 → 备份与恢复 → 导出 JSON 全量备份**，保存文件。
3. 同一区块点 **导出原图包（zip）**，选「全部」，保存文件。
4. 把这两个文件放到网盘或 U 盘。

**预期结果**：本地有两个文件 `个人综合管理备份-YYYY-MM-DD.json` 和 `原图包-YYYY-MM-DD.zip`，都能打开。
**⚠️ 易错提醒**：JSON 备份只有图片路径、没有图片本体，两个都要导，缺一不可。

## V6.2 第 2 步 · 执行数据库升级 SQL

1. Supabase → **SQL Editor → New query**。
2. 打开本机 `supabase/schema.sql`，**Ctrl+A 全选 → 复制**（不要只复制 PART IV！整份是幂等脚本，从头执行一次即可）。
3. 粘贴进 SQL Editor → **Run**。

**预期输出**：`Success. No rows returned`（有 `notice` 提示可忽略）。
**重复执行**：安全，不会丢数据，可以再跑一次验证幂等。

4. 再新建一次 query，粘贴 `supabase/selfcheck-image.sql` 全部内容 → Run。

**预期输出**：12 行结果；第 1、2、3、4、6、7、9 项 `status = OK`；第 5、8、10、11、12 项是 `INFO` 人工核对项。
**失败看哪里**：第 2 项不是 `=9` 说明 PART IV 没执行完整，回第 3 步重跑整份 SQL；第 3 项不是 1 说明桶被改成公开了，重跑整份 SQL 会改回私有。
