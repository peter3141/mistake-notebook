## 第 0 章 · 开始之前

### 0.1 名词小词典（不用背，遇到时回来查）

| 词 | 大白话 |
| --- | --- |
| Supabase | 帮你存数据的「云端仓库」，同时管登录账号和图片 |
| Vercel | 把网站放到公网上的「托管平台」，部署完给你一个网址 |
| 环境变量 | 网站运行时要用的「配置小纸条」，比如仓库地址、钥匙 |
| API Key | 调用 AI 的「钥匙」，**只能放在服务器上，绝不能发给别人** |
| Coding Plan | 阿里云百炼的一种**包月/包周套餐**，按「调用次数」算，不是按字数算 |
| Base URL | AI 服务的「门牌号」，Coding Plan 有专用门牌，走错门会扣错钱 |
| RLS | 仓库的「隔离规则」，保证每个人只能看到自己的错题 |
| 部署 | 把代码变成能打开的网站 |
| Redeploy（重新部署） | 改了配置后，让网站重新读一遍配置 |
| PWA | 把网站「添加到手机桌面」，像 App 一样打开 |

### 0.2 你要准备的东西

- [ ] 一个邮箱（注册 GitHub、Supabase、Vercel、阿里云都用得上）
- [ ] 一台电脑（Windows 或 Mac 都行）
- [ ] 一部手机（最后验证跨设备用）
- [ ] 想用 AI 的话：一个阿里云账号，并且**已订阅 Coding Plan 套餐**
- [ ] 大约 30–60 分钟，中间不要关掉浏览器标签页

> ⚠️ **最容易出错的第一名**：把「Coding Plan 专属 Key」和「普通百炼 Key」搞混。前者是 `sk-sp-` 开头，后者是 `sk-` 开头，**两者不通用**。第 21 步会反复提醒你。

## 阶段 A：把代码放进 GitHub（第 1–6 步）

> 这一步的目的：让 Vercel 能读到你的网站代码。GitHub 就是一个「代码网盘」。

**第 1 步：** 打开 https://github.com → 点右上角 `Sign up` → 用邮箱注册并登录。

> 📷【截图占位：GitHub 注册页，红框圈出 Sign up 按钮】

**第 2 步：** 点右上角 `+` → `New repository` → `Repository name` 填 `mistake-notebook` → 下面的 README / .gitignore / License **一个都不要勾** → 点最下面绿色 `Create repository`。

> 📷【截图占位：New repository 页面，红框圈出名字输入框和 Create repository 按钮】
> **易错提醒**：如果勾了 README，后面推送代码会冲突。勾了就删掉仓库重新建一次。

**第 3 步：** 在电脑上打开命令行。

- **Windows**：按键盘 `Win` 键，输入 `PowerShell`，点「Windows PowerShell」打开。
- **Mac**：按 `Command + 空格`，输入 `终端`，回车。

> 📷【截图占位：Windows 开始菜单搜索 PowerShell / Mac 聚焦搜索「终端」】

**第 4 步：** 复制下面整段，粘贴到窗口里，按回车。

**Windows PowerShell：**
```powershell
cd "$HOME\Documents"
mkdir mistake-notebook-repo
cd mistake-notebook-repo
git init
```
**Mac 终端：**
```bash
cd ~/Documents
mkdir mistake-notebook-repo
cd mistake-notebook-repo
git init
```
**预期输出**：
```
Initialized empty Git repository in .../mistake-notebook-repo/.git/
```
> **易错提醒（Windows 最常见的第一道坎）**：如果提示 `git : 无法将 "git" 项识别为 cmdlet、函数、脚本文件或可运行程序的名称`（等同于 `git: command not found`），说明**这台电脑还没装 Git**。两种装法选一个：
>
> **① 推荐 · 一行命令装（winget，Win10/11 自带）**，在 PowerShell 里执行：
> ```powershell
> winget install --id Git.Git -e --source winget --scope user --accept-package-agreements --accept-source-agreements
> ```
> 预期最后出现 `已成功安装` / `Successfully installed`（约 1–3 分钟）。
>
> **② 图形界面装**：打开 https://git-scm.com/download/win → 下载 64-bit Git for Windows → 一路 Next（默认选项不用改）→ 完成。
>
> ⚠️ **装完必须把当前 PowerShell 窗口整个关掉、重新开一个新窗口**：PATH 只在开窗口时读一次，不重开就会一直报同样的错。新窗口先验证：
> ```powershell
> git --version
> ```
> 预期 `git version 2.x.x.windows.x`。看到版本号再回到第 4 步。
>
> **如果重开窗口还是不认 `git`**（少数机器 PATH 没刷新）：先在当前窗口执行下面这一行即时生效，再验证；想一劳永逸就注销并重新登录一次 Windows（或重启）：
> ```powershell
> $env:PATH += ";C:\Program Files\Git\cmd"
> git --version
> ```
> 安装程序已经把 `C:\Program Files\Git\cmd` 写进**系统** PATH，重新登录后所有新窗口都能直接用 `git`。
>
> **如果第 4 步只跑了一半**（例如 `mkdir` 已经建好目录、卡在 `git init`），重开窗口后不用从头来，执行这两行即可：
> ```powershell
> cd "$HOME\Documents\mistake-notebook-repo"
> git init
> ```
> 预期 `Initialized empty Git repository in .../mistake-notebook-repo/.git/`。
>
> **Mac**：`git` 一般自带；若提示未安装，执行 `xcode-select --install`，或 `brew install git`。
>
> **临时应急（不想装也能继续，仅当前窗口有效）**：WorkBuddy 自带了一份 Git，在 PowerShell 里执行：
> ```powershell
> $env:PATH += ";E:\work\WorkBuddy\resources\vendor\PortableGit\cmd"
> git --version
> ```
> 但这个路径属于 WorkBuddy 内部目录、且**不带 GitHub 登录凭据管理器**，第 6 步 `git push` 可能仍要手动用 Personal Access Token。正式部署请用 ① 或 ②。

**第 5 步：** 把本项目 `mistake-notebook` 文件夹里的**所有文件**复制到刚才新建的 `mistake-notebook-repo` 文件夹里。

> **易错提醒**：
> - 复制的是「文件夹里面的东西」，不是把整个文件夹套进去。复制完应该直接看到 `package.json`、`app` 文件夹、`docs` 文件夹等。
> - **不要**复制 `.env.local`（里面有机密）。`.env.example` 要复制。
> - **不要**复制 `node_modules`（约 426 MB）和 `.next`（约 353 MB）：分别是依赖包和构建产物，Vercel 部署时会自己重新生成，复制过去只是白占 780 MB、还让 `git add .` 变慢。`.gitignore` 已忽略它们，但不该被复制。
> - **不要**复制 `.workbuddy`（WorkBuddy 的项目记录/记忆，属于本地数据，不进 GitHub；只忽略、不删除）。已加进 `.gitignore`。
>
> **推荐用命令一次复制对（PowerShell，整段粘贴）**：
> ```powershell
> $src = "C:\Users\peter\WorkBuddy\2026-11-08-15-58-43\mistake-notebook"
> $dst = "$HOME\Documents\mistake-notebook-repo"
> robocopy $src $dst /E /XD node_modules .next .workbuddy .vercel out build /XF .env.local *.tsbuildinfo
> ```
> 预期：末尾出现 `已复制` / `Copied` 统计。注意 `robocopy` 退出码 `1` 表示「成功复制了文件」，**不是报错**（≥8 才是失败）。
> 复制完用 `dir` 检查：应能看到 `package.json`、`app`、`components`、`docs`、`lib`、`supabase`、`.gitignore`、`.env.example`，且**没有** `node_modules`、`.next`、`.env.local`。
>
> 想手动复制也行：文件资源管理器里选中 `mistake-notebook` **里面的**全部内容 → Ctrl+C → 进 `mistake-notebook-repo` → Ctrl+V；然后手动把上面那几个目录排除掉。

**第 6 步：** 回到命令行，逐行执行（把 `你的用户名` 换成第 1 步注册的 GitHub 用户名）。

**先做一次（本机目前 `user.name` / `user.email` 都是空的，不先设 `git commit` 必定报错）**：

```powershell

git config --global user.name "你的名字"
```

然后逐行执行：

```bash
git add .
git commit -m "init: 错题本网站"
git branch -M main
git remote add origin https://github.com/你的用户名/mistake-notebook.git
git push -u origin main
```
**预期输出**：
```
Enumerating objects: 200+, done.   ← 数字不固定，几十到几百都正常
...
To https://github.com/你的用户名/mistake-notebook.git
 * [new branch]      main -> main
```
> **易错提醒**：如果提示 `Author identity unknown`，说明上面那两行 `git config` 没跑成功，重跑后再执行 `git commit`。
> 如果弹出登录窗口，选 `Sign in with your browser` 用浏览器授权。

**第 10 步：** 打开项目里的 `supabase/schema.sql` 文件（用记事本或 VS Code 都行），**全选 → 复制**，粘贴到 SQL Editor 的大白框里，点右下角 `Run`（或按 `Ctrl + Enter` / Mac 是 `Cmd + Enter`）。

> 🛑 **点 `Run` 后会弹出 `Potential issues detected` 对话框**（2026 年新版 SQL Editor 才有，旧版没有），里面写：
> - `This query includes destructive operations. It may permanently change or remove data, tables, schemas, or other objects.`
> - `This query creates tables without enabling Row Level Security...`
> - 底部三个按钮：`Cancel` / 橙色 `Run without RLS` / 绿色 `Run and enable RLS`
>
> **点橙色的 `Run without RLS`。别点 `Cancel`（等于什么都没跑）。** 为什么可以放心点：
> - 这两条是 SQL Editor 的**静态文本扫描提示，不是报错**。它看到脚本里的 `drop trigger if exists` / `drop policy if exists` / `create or replace function` / `alter table ... drop constraint`，以及函数定义里的 `delete from`（那只是**定义**清理函数，建库时并不会执行），就一律标成 destructive。首次在空库执行不会删掉任何数据；这些 `... if exists` 都是幂等重建，重复跑也安全。
> - **`Run without RLS` 不是「把 RLS 关掉」**，它只是不让平台额外插手、SQL 原文照常执行。这份 `schema.sql` 自己在第 368 / 802 / 1225 行有三段循环，逐表 `alter table ... enable row level security` 并创建 `own_rows` 策略，**31/31 张表全覆盖**；第 11 步会亲眼验证 31 行 `rls=true`。
> - 绿色 `Run and enable RLS` 是给「SQL 里压根没写 RLS」的人兜底的：它会在查询后再补一次 `enable row level security`（幂等，重复无害，**选它也不会弄坏**），但只开 RLS、不建策略。本项目用不上，而且和第 8 步 `Enable automatic RLS` 不勾是同一口径：RLS 全由脚本掌控。

**预期输出**：右下角出现绿色
```
Success. No rows returned
```
> 📷【截图占位：SQL Editor，红框圈出粘贴区和 Run 按钮，右下角显示 Success】
> ⚠️ **易错提醒**：必须**整份**粘贴，只粘一半会导致后面图片传不上、RLS 没开。看到红色报错就把报错文字复制发我。
>
> 🔴 **如果报 `ERROR: 42501: must be owner of table objects`**：说明你粘的是**旧版** `schema.sql`——里面有一句 `comment on table storage.objects ...`。`storage.objects` 归 Supabase 内部角色 `supabase_storage_admin` 所有，SQL Editor 连接的 `postgres` 既不是 owner 也不是 superuser，`supautils` 只代理 policy 语句、不代理 `COMMENT` / `ALTER TABLE`，所以这一句会被拒并**中断整份脚本**。
> **处理**：新版脚本已把这句改成普通 SQL 注释（信息没丢）。重新打开本机 `supabase/schema.sql` → 全选复制 → 回 SQL Editor 全选粘贴 → `Run` → 弹窗仍点 `Run without RLS`。脚本是幂等的，重跑不会删数据、不会重复建表。
>
> 若重跑**仍**报同样 42501，先单独新建 query 跑这段探针，把结果发我：
> ```sql
> drop policy if exists "zz_probe" on storage.objects;
> create policy "zz_probe" on storage.objects for select to authenticated using (false);
> drop policy if exists "zz_probe" on storage.objects;
> ```
> 探针通过 = policy 语句有权限，整份重跑即可成功；探针也报 42501 = 该项目不允许 SQL Editor 在 `storage.objects` 上建策略，改走 **Storage → `mistake-images` → Policies** 图形界面手工建 4 条：`SELECT` / `INSERT` / `UPDATE` / `DELETE`，角色 `authenticated`，表达式统一为 `bucket_id = 'mistake-images' and (storage.foldername(name))[1] = auth.uid()::text`（UPDATE 的 `using` 和 `with check` 都填这一句）。

**第 11 步：** 再点一次 `New query`，把下面**这一条**粘进去、点 `Run`：

```sql
select
  (select count(*) from pg_tables where schemaname='public') as tables_total,
  (select count(*) from pg_tables where schemaname='public' and rowsecurity) as rls_true,
  (select count(*) from pg_policies where schemaname='storage' and tablename='objects' and policyname like 'img_%') as img_policies,
  (select public from storage.buckets where id='mistake-images') as bucket_public;
```

**预期输出（一行四个值）**：`31 | 31 | 4 | false`
- `31 / 31` = 31 张业务表全部开启 RLS；
- `4` = `storage.objects` 上 4 条图片策略（`img_select_own` / `img_insert_own` / `img_update_own` / `img_delete_own`）都建成了——**上一环节报过 42501 的项目尤其要确认这一格**；
- `false` = 图片桶私有，别人猜到链接也打不开，是**好事**。

> ⚠️ **别把两句 select 放在同一个 query 里跑**：新版 SQL Editor 的 `Results` 面板**只显示最后一条语句的结果**。按老写法同时跑 `select tablename, rowsecurity ...;` 和 `select id, public from storage.buckets ...;`，只会看到后一句的 `mistake-images | false`，第一句的 31 行被盖住了——**这不代表表没建**。想逐行看 31 张表，就单独跑第一句。
> 📌 早期版本手册这里写「16 行」，那是 v1 口径；现在整份 `schema.sql` 建 31 张表。
> 只要有一格对不上（例如 `rls_true < 31`、`img_policies < 4`），单独跑 `select tablename, rowsecurity as rls from pg_tables where schemaname='public' order by tablename;`，把结果发我。

## 2.3 按时间、科目、标签、错因、掌握状态筛选（第 42–45 步）

**第 42 步：** 点「错题」进入列表，最上面是筛选区：搜索框可以直接搜**题目 / 答案 / 解析 / 标签 / 知识点 / 来源**。

**第 43 步：** 右边的下拉框依次是：科目、错题本、标签、错因、难度、掌握状态，按需选。选完列表立刻变化。

**第 44 步：** 第二行的「时间依据」可以切换成「错题发生时间 / 录入时间 / 复习时间」，再填起止日期。「排序」可选最新、最旧、待复习优先、错误次数优先。

**第 45 步：** 「分组」选「按周分组 / 按月分组 / 时间轴 / 日历视图」。日历视图会出现一格格日期，点某天就只看那天的错题。

## 2.4 AI 整理 → 预览 → 确认应用 → 回滚（第 46–50 步）

> 前置：设置页 AI 总开关是「已开启」，且「AI整理错题」子开关打开。关闭时按钮是灰的，属于正常现象。

**第 46 步：** 打开一道错题 → 点「AI整理」（有图片时会自动用视觉模型一起看图片）。

**第 47 步：** 等几秒，出现「AI 整理结果预览（尚未写入）」。**这一步什么都没改**，你可以直接关掉页面，原题毫发无损。

**第 48 步：** 检查预览内容，觉得可以就点「**确认应用（填入编辑区，仍需点保存）**」→ 内容会填进标题、正文、答案、解析、知识点、错因、难度、标签 → 再点「**保存**」才真正写进云端。

**第 49 步：** 如果发现 AI 整理错了，点「**历史版本**」→ 会列出每次保存前的快照（数据库自动记录）→ 点对应版本的「**回滚**」→ 弹窗确认 → 刷新页面，内容就回到那一版。
> 回滚本身也会产生一个新版本，所以回滚错了还能再滚回来。

**第 50 步：** 详情页最下面的「相似题推荐」可以生成 3 道练习题。这些题**全部标注「AI生成，需核对」**，不会进题库、不会被随机组卷抽到，别直接当标准答案用。

> **批量整理**：列表页勾选多道 → 点「AI批量整理」→ 弹窗先告诉你「预计调用 N 次」→ 确认后逐条跑并显示进度 → 结果先列表预览 → 点「确认应用全部成功项」才写库。
> 缓存命中不会重复调用，失败最多重试 1 次，4xx/429 不重试。

## 2.5 OCR 识题（第 51–53 步）

**第 51 步：** 新建/编辑错题时插入一张带文字的图 → 点图片右上角的**扫描小图标**。

**第 52 步：** 出现「OCR 识别结果（请核对后再填入）」，文字和公式都在预览框里。**不点按钮不会改动正文**。

**第 53 步：** 核对错别字和公式 → 点「填入题目正文」→ 再保存。
> **识别失败怎么办**：会弹出提示，但**原图一定还在**，你直接手动打字即可，完全不阻塞录题。这就是「失败不阻塞」的设计。

## 2.6 今日待复习、标记状态、安排下次复习（第 54–57 步）

**第 54 步：** 首页有「今日待复习」数字和列表；点「复习」进入复习页。

**第 55 步：** 每道题下面填「本次复习备注」（可选，比如"又忘了讨论判别式"）。

**第 56 步：** 点三个结果之一：
- **不会 / 又错**：回到第 1 档间隔（默认 1 天后），错误次数 +1
- **模糊**：保持当前间隔
- **已掌握**：进入下一档（默认 1→2→4→7→15→30 天）

**第 57 步：** 想改间隔：设置页「艾宾浩斯复习间隔」输入 `1,2,4,7,15,30`（数字用逗号隔开），鼠标点别处就自动保存。下面「复习日志」能看到每次复习的时间和结果。

## 2.7 随机组卷与错题重练（第 58–60 步）

**第 58 步：** 点「复习」页里的「去随机组卷练一练」，或网址加 `/review/random`。选科目/错题本/标签/错因/难度/时间范围/题量 → 点「随机抽题」。
> **这一步完全不依赖 AI**，关闭 AI 后照样能抽题。

**第 59 步：** 点「显示答案」切换成答案版；点「生成练习卷 / 打印 / PDF」跳到打印页。

**第 60 步：** 给每道题点「又错 / 模糊 / 已掌握」→ 点「保存重练结果」，会自动更新掌握状态和错误次数，并写进重练记录。

## 2.8 打印与导出 PDF（第 61–62 步）

**第 61 步：** 四种进入方式：
1. 列表页勾选题 →「打印选中」
2. 列表页 →「按筛选结果打印」
3. 详情页 →「单题打印」
4. 随机组卷 →「生成练习卷」

**第 62 步：** 打印预览页：
- 选模板：**学生版**（只有题+答题空行）、**答案版**（带答案解析）、**复习版**（带知识点和复习信息）、**错因复盘版**（带错因和解析）
- 勾选要打印的字段：答案、解析、知识点、标签、图片、错因、复习建议、页眉
- 点「**打印 / 导出PDF**」→ 浏览器打印对话框 → 目标选「**另存为 PDF**」→ 纸张 **A4** → 勾「背景图形」→ 保存
- 常用配置点「保存为模板」，下次在「已存模板」一点就套用；设置页可删除模板

> ⚠️ **打印效果不好时**：见第三部分第 76 步（分页/图片截断调整）。

## 2.9 备份、分享、回收站、PWA（第 63–68 步）

**第 63 步：** 设置页 →「导出 JSON 全量备份」→ 得到一个 `.json` 文件 → **另存到网盘或 U 盘**。建议每月一次（免费版 Supabase 不含自动备份）。想用 Excel 看就点「导出 CSV」。

**第 64 步：** 恢复备份：把 JSON 文件用记事本打开 → 全选复制 → 粘进设置页「恢复备份」输入框 → 点「**预览 / 字段映射**」→ 看到「共 N 道 + 字段对应关系」→ 点「**确认导入 N 道**」。
> 导入是**按新 id 追加**，不会覆盖现有错题。图片记录的是云端路径，要恢复图片需保留原来的图片桶。

**第 65 步：** 生成只读分享：列表页点「生成只读分享」→ 出现绿色链接 → 点「复制」发给别人。
- 对方**不用登录**就能打开，只能看，没有任何编辑按钮，也看不到你的账号信息和 AI 结果
- 默认 **7 天过期**，点「取消分享」立刻作废；设置页可以看到历史分享

**第 66 步：** 恢复误删：点「回收站」→ 找到题目 → 点「恢复」。想永久删除点「彻底删除」；「清空回收站」必须**手动输入「清空」**两个字才能点，防手滑。

**第 67 步：** 手机添加到桌面（PWA）：
- **iPhone（Safari）**：打开网站 → 底部「分享」按钮（方框带向上箭头）→ 下滑选「添加到主屏幕」→ 点「添加」
- **Android（Chrome）**：右上角 `⋮` → 「添加到主屏幕 / 安装应用」→ 确认

**第 68 步：** 离线时：已经看过的页面还能打开，但顶部会出现橙色提示「当前离线：只能查看已缓存内容，暂时无法保存/上传」，**保存按钮被禁用**，防止把旧内容偷偷覆盖云端。恢复网络后变绿色提示「网络已恢复，可以继续同步数据」，这时再点保存即可。

## 2.10 统计页看薄弱点（第 69–70 步）

**第 69 步：** 点「统计」→ 上面选时间范围（近 7/30/90 天或全部）和科目。

**第 70 步：** 看三块：
- **错因分类统计**：7 类错因各有多少题（计算错误、概念不清、审题错误、公式记错、步骤遗漏、粗心、其他）
- **知识点热力图**：颜色越红的知识点错得越多，下面直接列出「最该先复习的 5 个薄弱点」
- **复习完成率 + 新增趋势**：按周/月看新增错题数

> 💡 知识点热力图要填了「知识点」字段才有内容。录题时顺手填一下，统计才有意义。

## 2.11 【专题】AI 开关完全指南（务必读一遍）

### 怎么开 / 怎么关

| 想做的事 | 点哪里 |
| --- | --- |
| 关闭全部 AI | 设置页 → 「启用AI功能（总开关）」拨成灰色 |
| 重新开启 AI | 同一处拨成紫色 → **不需要重新部署、不需要改代码**，立刻生效 |
| 只关 OCR，保留 AI 整理 | 设置页 → 子开关「OCR / 图片识题」关掉，其余留开 |
| 只关相似题 | 关「相似题推荐」子开关 |
| 禁止批量烧配额 | 关「AI批量整理」子开关 |
| 全部恢复出厂设置 | 点「恢复默认」（总开关会回到**关闭**） |

### 关闭 AI 后

**不可用**：AI整理、AI批量整理、OCR/图片识题、相似题推荐、AI 组卷建议（本来就是手动抽题，不受影响）。所有入口会**隐藏或置灰**并显示「AI功能已关闭」。
**完全不受影响**：新建/编辑错题、插入图片和拍照、富文本和公式、时间分类、日历/时间轴、筛选搜索、复习闭环、随机组卷（手动抽题）、打印与导出 PDF、打印模板、回收站、JSON/CSV 备份恢复、只读分享、统计页、PWA 离线查看。
**服务端硬保证**：就算有人懂技术、绕过页面直接请求 `/api/ai/organize`，服务器也会在**发起任何外部调用之前**返回 `403`「AI功能已关闭」。前端隐藏只是体验，服务端拒绝才是真保险。

### 未配置 Key 时

设置页出现黄色框「**AI未配置**」，下面列出具体缺什么（例如「DASHSCOPE_CODING_API_KEY 未配置」）。所有 AI 入口自动禁用，**页面不会白屏、不会报错**，手动功能全部正常。
补配方法：按第 22–24 步在 Vercel 补上变量 → Redeploy → 回设置页打开总开关。

### 怎么确认「关闭后没有再产生费用」

1. 设置页看顶部状态必须是 `AI功能当前状态：已关闭`。
2. 记下「累计成功调用：N 次」，过几分钟刷新，**数字不变**就说明没有新调用。
3. 想更彻底：在浏览器控制台（F12 → Console）粘贴下面这行并回车：
   ```js
   fetch('/api/ai/organize',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({title:'测试'})}).then(r=>r.json()).then(console.log)
   ```
   **预期输出**：`{error: 'AI功能已关闭', code: 'AI_DISABLED'}`（HTTP 403）。
4. 到阿里云百炼 Coding Plan 页面看本周/本月用量不再增长。

### 开关会同步吗

会。开关存在数据库的 `user_settings` 表里，刷新页面、退出重登、换手机、换网络，状态都一致。

# 第三部分 · 维护与排错教学

## 3.1 怎么看部署日志和报错（第 71–72 步）

**第 71 步：** Vercel → 选你的项目 → 顶部 `Logs`（或 `Deployments` → 点某次部署 → `Build Logs` / `Runtime Logs`）。

**第 72 步：** 网页上遇到红色报错时，按 `F12` → 点 `Console`（控制台）→ 把红色文字复制；再点 `Network` → 点失败的那条请求 → 看 `Response`。
> 发给我时**只发报错文字**，不要发任何 Key。

## 3.2 Coding Plan 报错速查表（第 73 步）

**第 73 步：** 对照下表处理（设置页的 AI 卡片和 AI 整理失败提示都会显示中文原因）：

| 报错 | 大白话原因 | 一步步怎么修 |
| --- | --- | --- |
| `401 invalid access token` | Key 不对 / 过期 / 被重置过 | ① 百炼 → Coding Plan → 重置或重新复制 `sk-sp-` Key ② Vercel → `DASHSCOPE_CODING_API_KEY` 改成新值 ③ Redeploy ④ 设置页确认「已开启」 |
| `model 'xxx' is not supported` | 模型 ID 拼错 / 不在套餐支持列表 / 订阅失效 | ① 检查 `AI_MODEL`/`VISION_MODEL`/`OCR_MODEL` 是否为 `qwen3.7-plus` 这类**完整精确 ID** ② 别写 `qwen3.7`、别有空格、注意大小写 ③ 去控制台确认 Coding Plan 订阅仍有效 ④ 改完 Redeploy |
| `403 invalid api-key` | **误用了百炼通用按量计费的 Base URL 或普通 `sk-` Key** | ① `AI_BASE_URL` 必须是 `https://coding.dashscope.aliyuncs.com/v1` ② Key 必须 `sk-sp-` 开头 ③ 确认没有 `compatible-mode/v1`、`maas.aliyuncs.com` 字样 ④ Redeploy。**这一步做错会产生额外按量扣费，优先检查** |
| `404` | Base URL 路径写错 | 只填到 `/v1` 为止，**不要**在后面加 `/chat/completions`，代码会自动拼；也不要漏掉 `/v1` |
| `429 / quota exceeded` | 请求太密，或套餐本周/本月次数用完了 | ① 等几分钟再试 ② 周额度**每周一 00:00（北京时间）**重置，月额度在订阅日重置 ③ 先把 AI 总开关关掉，避免继续消耗 ④ 关掉「AI批量整理」、少做批量 ⑤ 升级套餐 |
| `请求超时 / 无法连接` | 网络抖动或图片太大 | ① 稍后重试（最多自动重试 1 次） ② 图片太大时先裁一下再传 ③ 仍失败就关掉 AI，手动录入不耽误 |
| `AI未配置` | Vercel 里少了变量，或改完没 Redeploy | 按第 22–24 步补齐并重新部署 |

> ⚠️ **改任何环境变量之后，都必须 Redeploy 一次**，否则网站还在用旧配置。这是最常见的「我明明改了怎么没生效」。

## 3.3 图片问题（第 74–75 步）

**第 74 步：上传失败**
1. 回 Supabase → `Storage` → 看有没有 `mistake-images` 桶，且是 **Private**（私有）。没有 → 重新执行第 10 步的 `schema.sql`。
2. Vercel 日志里如果看到 `new row violates row-level security policy`，说明第 10 步 SQL 没跑完整 → 重跑一次（脚本可以重复执行，不会破坏已有数据）。
3. 确认图片格式是 jpg/png/webp/gif，单张不超过 50 MB（网站会自动压到 1600px，一般远小于此）。
4. 手机拍照失败：检查浏览器相机权限（第 39 步）。

**第 75 步：图片不显示（显示破图）**
1. 刷新页面 —— 私有桶的签名 URL **1 小时过期**，刷新会重新签名。
2. 检查 Supabase 项目是不是被暂停了（免费版 7 天无访问）→ 控制台 `Restore project`。
3. 浏览器 F12 → Network 看图片请求是不是 `403`：多半是 Storage 策略没建好 → 重跑 SQL。

## 3.4 打印分页 / 图片截断（第 76 步）

**第 76 步：** 按顺序试：
1. 打印对话框里确认**纸张是 A4、缩放 100%**、勾上「背景图形」，别选「每张纸打印 2 页」。
2. 图片太大：打印页把「图片」勾掉试一次，确认是不是图片导致；需要图片就把原图裁小一点再上传。
3. 题目被拆到两页：这是 CSS `break-inside: avoid` 在生效，正常情况下不会发生。若发生，把打印页的「解析」「复习建议」等字段少勾几项，让单题变短。
4. 想每道题单独一页：让开发在 `app/globals.css` 的 `.print-block` 里加 `break-before: page;`（这一步可以把这句话发给我，我帮你改）。
5. 导出 PDF 一定用 **Chrome / Edge** 的「另存为 PDF」，Safari 的 PDF 排版偶有差异。

## 3.5 更新代码后重新部署（第 77 步）

**第 77 步：** 改完文件，在命令行执行：

**Windows PowerShell 与 Mac 终端命令相同：**
```bash
git add .
git commit -m "update"
git push
```
**预期输出**：
```
Enumerating objects: 5, done.
...
To https://github.com/你的用户名/mistake-notebook.git
   abc1234..def5678  main -> main
```
然后 Vercel 会自动开始新的部署，1–3 分钟后状态变 `Ready`。也可以手动 `Deployments → ... → Redeploy`。
> **只是改设置页的 AI 开关、复习间隔、提示词、打印模板，都不需要动代码、不需要重新部署**，在网页上改完立刻生效。

## 3.6 更换 Coding Plan 模型或 API Key（第 78 步）

**第 78 步：**
1. 换 Key：百炼 Coding Plan 页面重置/复制新 `sk-sp-` Key → Vercel 改 `DASHSCOPE_CODING_API_KEY` → **Redeploy**。
2. 换模型：Vercel 改 `AI_MODEL` / `VISION_MODEL` / `OCR_MODEL` → **Redeploy** → 设置页核对显示的模型名。
3. 换完随手点一次「AI整理」验证；如果报 `model ... is not supported`，回第 73 步。
> ⚠️ 换视觉模型时，**一定要选标注支持图片理解的**（`qwen3.7-plus` / `qwen3.6-plus` / `kimi-k2.5`），否则 OCR 会失败。

## 3.7 备份与恢复（第 79 步）

**第 79 步：** 照第 63–64 步做一遍。额外提醒：
- 建议**每次大改之前**（比如清空回收站、注销前、换模型前）先导出一份。
- 恢复时先点「预览 / 字段映射」，确认条数和字段对应没错，再点「确认导入」。
- JSON 备份里包含图片在云端的**路径**，不含图片文件本身。要连图片一起保住，别删 Supabase 的 `mistake-images` 桶。

1. 设置页显示 `AI功能当前状态：已关闭`。
2. 设置页「累计成功调用：N 次」**隔一会儿刷新，数字不再增加**。
3. 刷新任意页面，按 **F12** → **Network（网络）** → 过滤 `api/ai`，除了 `/api/ai/status`（只读状态、不花钱）以外，**没有任何其它请求**。

- 设置页显示橙色提示 **「AI未配置」** 并列出到底缺哪一项；
- 所有 AI 入口自动禁用；
- **页面不会白屏、不会报错**，非 AI 功能全部正常。

补齐方法：Vercel → Project → Settings → Environment Variables 填这两个值 → **一定要 Redeploy 一次** → 回来打开总开关。详细步骤见第一部分「阶段 D」与第三部分 3.2 / 3.6。

### 第 7 步：重新开启 AI（不需要重新部署）

1. `/settings` → 把「启用AI功能」点成蓝色。
2. 确认需要的子开关也是开的。
3. **不用碰 Vercel、不用改环境变量、不用重新部署**，立刻生效。
4. 到 `/calendar` 输入一句话点「生成预览」，或到错题详情点「AI整理」，能出预览就是成功。

### 第 8 步：换设备会不会失效

**不会。** 开关存在云端的 `user_settings` 表里。手机上关掉，电脑刷新后也是关的；退出重新登录、换网络都保持一致。

## 5.12 Coding Plan 配置与报错（增量补充）

> 开通方式、`sk-sp-` 专属 Key 与普通按量计费 Key 的区别、Base URL 为什么必须是 `https://coding.dashscope.aliyuncs.com/v1`、文本模型与视觉模型怎么选 —— **这些在第一部分的「阶段 D」和第三部分 3.2 已经完整写过，一个字没改，请回看**。

新增的两个 AI 能力用的是**纯文本模型 `AI_MODEL`（默认 `qwen3.7-plus`）**，**不调用视觉模型**，所以：

- 即使 `VISION_MODEL` 配错，只要不用 OCR / 图片整理，日程解析和笔记总结仍能正常工作；
- 反过来，OCR / 图片识题仍然必须用明确支持图片理解的模型（`qwen3.7-plus` / `qwen3.6-plus` / `kimi-k2.5`）。

常见报错速查（完整版见第三部分 3.2）：

| 报错 | 最常见原因 | 一句话处理 |
| --- | --- | --- |
| `401 invalid access token` | `sk-sp-` Key 不对 / 过期 | 去 Coding Plan 控制台重新复制 Key → Vercel 改 `DASHSCOPE_CODING_API_KEY` → Redeploy |
| `model 'xxx' is not supported` | 模型 ID 拼错或不支持 | 改成精确版本 `qwen3.7-plus`，注意大小写、不要空格 |
| `403 invalid api-key` | 误用了通用按量计费 Base URL | `AI_BASE_URL` 必须固定 `https://coding.dashscope.aliyuncs.com/v1` |
| `404` | Base URL 路径写错 | 末尾不要加 `/chat/completions`，代码会自动拼 |
| `429 / quota exceeded` | 请求太密或套餐额度用完 | 等额度重置；先关 AI 总开关止损；开启时有每分钟 10 次 / 每天 100 次限流 |

> ⚠️ 再次强调：Coding Plan 的专属 Key（`sk-sp-` 开头）**不消耗百炼通用免费 Token 额度**，也**不能**和普通 `sk-` Key 混用，更不能用 `compatible-mode/v1` 或 `maas.aliyuncs.com` 端点，否则鉴权失败或产生额外扣费。

## 5.14 常见问题 FAQ（v2）

**Q：升级会不会把我原来的错题弄丢？**
A：不会。SQL 里所有建表都是 `if not exists`，加列也是 `if not exists`，不会删任何数据。不放心就先去 `/settings` 导出一次 JSON 备份。

**Q：我完全不用 AI，需要配阿里云吗？**
A：**完全不需要**。不填 `DASHSCOPE_CODING_API_KEY` 和 `AI_BASE_URL` 也能正常部署和使用，设置页会提示「AI未配置」，其它功能一个不少。

**Q：关闭 AI 后手机上还能拍照上传吗？**
A：能。拍照、压缩、上传、插入笔记或错题都是本地 + Supabase Storage 完成的，跟 AI 无关。只是「OCR 自动识别文字」不可用，改成手动输入，原图不会丢。

**Q：关掉 AI 后随机组卷还能用吗？**
A：能，走**手动选题**。只有「AI 组卷建议」这类智能推荐会隐藏。

**Q：新模块的数据在另一台设备上能看到吗？**
A：能，和错题一样走同一套 Supabase + RLS，登录同一账号即同步。AI 开关状态也是同步的。

**Q：分享链接会不会泄露我的其它数据？**
A：不会。分享是「单题 / 单个错题本 / 筛选结果 / 单篇笔记 / 单条日程」范围，服务端只取白名单字段，隐藏账号信息与隐私字段，且**带过期时间、可随时在设置页取消**。

**Q：我该先学哪一步？**
A：先做 5.1 升级 → 打开首页看聚合卡片 → 按 5.2 建一条日程 → 按 5.3 建一个待办 → 用 5.9 搜一下。剩下的按需看。

## 6.0 先读这一页（3 分钟）

这次补上了之前 4 项没做完的功能：**导出 Word、导出 Anki 卡片、本地离线 OCR、习惯历史日期补录**。

请先看这 4 句话，后面就不容易踩坑：

1. **Word 导出的图片是「跟着文件走」的**：图片已经真真正正塞进 `.docx` 里了，换一台电脑、断网、把文件发给别人，图片都还在。不是链接，也不会丢。
2. **Anki 用的是「一个压缩包」，不是 `.apkg` 文件**：⚠️ **`.apkg 未实现，已用 CSV/TSV 替代`**。你要做的是「解压 → Anki 文件→导入 → 字段对应 → 图片放好」，下面 6.2 有完整步骤，一步一步照做即可。
3. **本地 OCR 第一次会慢**：因为要下载约 20MB 的识别引擎和中文+英文语言包。下载完会存在浏览器里，之后就能离线用、速度也快了。慢的时候**不要关页面**，等 30–60 秒。
4. **习惯补录会立刻重算统计**：补一天卡，连续天数、月视图圆点、本月次数会**自动变**，不用刷新页面。算法与影响范围在 6.4 讲清楚。

> ⚠️ **未真实联调**：助手没有你的账号，没有替你建库、部署，也没有真的在 Word / Anki / 手机上打开过导出文件。所有「怎么用」都写全了，但**「真的能用」要你按 6.7 的《真实联调清单》验一遍**。

## 6.1 怎么导出 Word（单题 / 多题 / 按筛选结果）

### 第 1 步：先准备一道带图的错题（第一次建议这么做）

打开 `/mistakes` → 点「新建错题」→ 填标题 → 在「题目图片」处点「拍照」或「相册 / 选文件」上传 1 张图 → 点「保存到云端」。
**为什么先带图**：这样导出后一眼就能看出图片有没有真的进去。

### 第 2 步：单题导出

打开这道题的详情页 `/mistakes/某串id` → 在编辑区上方找到「**导出这道错题**」这一行 → 点「**导出 Word**」。

**预期看到**：按钮上方出现进度条，依次显示「正在读取错题」→「正在内嵌图片 1/1」→「正在生成 Word 文档」→「已完成」，随后浏览器自动下载一个 `错题本-Word-xxx.docx`。

> `[截图占位：导出进度条 + 下载提示]`

### 第 3 步：用 Word / WPS 打开检查

双击下载的文件。
**预期看到**：A4 纸张、标题、科目/错题本/错因/难度/知识点/标签、题目正文、**图片直接显示在题目下面**、答案、解析。
**如果只看到一串 `https://...` 或空白框**：说明图片没内嵌成功，看 6.6 排错。

### 第 4 步：验证「换电脑不丢图」（强烈建议做一次）

把这个 `.docx` 复制到另一台电脑（或发给自己的微信文件传输助手，在手机上打开），**断网**再打开。
**预期**：图片依然在。因为图片已经写进 `word/media/` 里了。
**结论**：Word 导出不依赖网站、不依赖网络，文件本身就是完整的。

### 第 5 步：多题 / 按筛选结果导出

回到 `/mistakes` 列表页，找到「选中的 N 道 → 导出」和「当前筛选结果（共 N 道）→ 导出」两个区域：

- **选中多题**：勾选几道题前面的方框 → 在左边区域点「导出 Word」。
- **按筛选结果**：先用上方筛选栏选好科目 / 时间 / 掌握状态 → 在右边区域点「导出 Word」。导出的是**符合当前筛选的全部题目**（不只是本页显示的 20 道）。

**单次上限 300 道、40 张图、6MB 图片**。超了会在页面出现黄色提示框，告诉你跳过了什么、原图还在云端、缩小范围再导一次即可。

### ✅ 6.1 阶段三句话

- **这个阶段我要做什么**：导出一份带图的 `.docx`，用 Word 打开，再换台电脑断网打开一次。
- **怎么验证成功**：两处都能看到图片，且不是链接文字。
- **下一步该对我说什么**：`Word 导出验过了，图片正常` 或 `Word 里图片是空白：[截图]`。

## 6.2 怎么导出 Anki 并成功导入（**重点，步骤最多，别跳步**）

> 再次说明：**`.apkg 未实现，已用 CSV/TSV 替代`**。你拿到的是一个 `.zip` 压缩包，里面是 Anki 官方支持的「文本文件 + 媒体文件夹」格式，Anki 桌面版可以直接导入。

### 第 1 步：导出

在错题详情或错题列表点「**导出 Anki**」→ 等进度条走完 → 下载 `错题本-Anki-xxx.zip`。

### 第 2 步：完整解压（**最容易错的一步**）

**Windows**：在下载的 zip 上点右键 → 「全部提取…」→ 选一个文件夹（例如桌面新建 `anki导入`）→ 点「提取」。
**macOS**：双击 zip，系统会自动在同级目录生成一个同名文件夹。

**预期看到 4 样东西**（缺一样就说明没解压完整）：

```
mistakes.tsv              ← 卡片文本，Tab 分隔
mistakes.csv              ← 备用，逗号分隔
mistakes.tsv.media/       ← 文件夹，里面是 m_xxxx.png / .jpg 图片
导入说明.txt              ← 上面这些步骤的文字版
```

> ⚠️ **不要只把 `mistakes.tsv` 单独拖出来导入**，那样图片会丢。整个文件夹要保持在一起。
> `[截图占位：解压后的 4 个文件/文件夹]`

### 第 3 步：打开 Anki 的导入窗口

打开 Anki 桌面版 → 顶部菜单「**文件**」→「**导入**」→ 选择刚才解压文件夹里的 `mistakes.tsv`。

### 第 4 步：字段对应（照着填，一项都不能错）

| 导入对话框里的项 | 填什么 / 选什么 | 为什么 |
| --- | --- | --- |
| 笔记类型 | `Basic` | 只有 Front / Back 两个字段，最省事 |
| 牌组 | 新建「错题本」或选已有牌组 | 卡片放哪 |
| 字段分隔符 | `Tab`（制表符） | 我们给的是 TSV |
| **第 1 列 →** | **Front（正面）** | 题干 + 图片 |
| **第 2 列 →** | **Back（背面）** | 答案 + 解析 + 知识点 + 错因 + 标签 + 科目难度 |
| 允许在字段中使用 HTML | ✅ **必须勾** | 不勾的话 `<img src=...>` 会变成一串文字，图片就不显示 |
| 忽略第一行 | ❌ **不要勾** | 文件没有表头，第一行就是第一张卡片 |
| 重复处理 | 按需选「更新已有笔记」或「忽略」 | 重复导入同一批题时用 |
| 导入媒体 | 保持默认 | Anki 会自动从同名 `.media` 文件夹带走图片 |

> `[截图占位：Anki 导入对话框，字段对应那几行]`

### 第 5 步：点「导入」并翻卡片

**预期看到**：导入成功提示 + 卡片数量；进入牌组翻卡片，**正面是题干和图片，背面是答案、解析、知识点、错因、标签**。

### 第 6 步：图片怎么处理（如果碎图就看这里）

正常情况 Anki 会自动从 `mistakes.tsv.media/` 里把图片带进媒体库。如果卡片上出现破图标，手动放一次：

- **第 6.1 步**：打开 `mistakes.tsv.media` 文件夹，全选里面所有图片，复制。
- **第 6.2 步**：打开 Anki 的媒体文件夹：
  - **Windows**：按 `Win + R`，粘贴下面这行，回车（把 `你的账户名` 换成 Anki 里显示的名字）：
    ```
    %APPDATA%\Anki2
    ```
    进入后打开你的账户文件夹 → `collection.media`，把图片粘贴进去。
  - **macOS**：Finder 按 `Shift + Command + G`，粘贴：
    ```
    ~/Library/Application Support/Anki2
    ```
    进入账户文件夹 → `collection.media`，粘贴图片。
  - 找不到？Anki 里点「工具 → 检查媒体」，能看到媒体库位置相关提示。
- **第 6.3 步**：**重启 Anki**，再翻卡片。

**为什么这样就好**：TSV 里写的是 `<img src="m_xxxx.png">`，Anki 只按文件名去自己的媒体库找图；文件在，图就显示。

### 第 7 步（可选）：Tab 导入不对时改用 CSV

如果导入预览里字段全挤在第 1 列，改选 `mistakes.csv`，并把分隔符改成「逗号」，其余设置完全一样。

### ✅ 6.2 阶段三句话

- **这个阶段我要做什么**：解压 zip → Anki 文件→导入 → 按表做字段对应 → 检查卡片正反面和图片。
- **怎么验证成功**：能翻到卡片，正面有题干和图片，背面有答案/解析/知识点/错因/标签。
- **下一步该对我说什么**：`Anki 导入成功，图片正常` 或 `Anki 显示碎图：[卡片截图 + 解压后的文件列表截图]`。

## 6.3 本地 OCR 怎么用（AI 关掉也能用）

### 6.3.1 它和 AI OCR 有什么不同（一句话版）

| | 本地 OCR（绿色扫描线按钮） | AI OCR（蓝色按钮） |
| --- | --- | --- |
| AI 总开关关闭时 | ✅ **照常可用** | ❌ 隐藏，点了也会被服务端拒绝 |
| 图片去哪 | **只留在这台设备的浏览器里，不上传** | 经服务端发给 Coding Plan 视觉模型 |
| 花钱吗 | **0 元，零 API 调用** | 受 Coding Plan 配额和限流约束 |
| 支持什么 | 印刷体中文简体 + 英文（其他语言按需加） | 中英文、公式、复杂排版，更准 |
| 公式 | **只给文字，不生成 LaTeX** | 能理解公式 |
| 网络 | 首次下载引擎+语言包，之后可离线 | 每次都要联网 |

### 第 1 步：确认 AI 是关着的（这样才能验证「零调用」）

`/settings` → 找到「启用AI功能」总开关 → 关掉 → 确认页面显示「AI功能当前状态：已关闭」。

### 第 2 步：上传一张有字的图

新建错题或编辑已有错题 → 「题目图片」→ 拍照 / 选文件 / 拖拽 / Ctrl+V 粘贴，任选一种。
**建议第一次用印刷体中文或英文的清晰截图**，别用手写潦草字，成功率高。

### 第 3 步：点绿色的「扫描线」按钮

每张图片右上角有两个图标：
- 蓝色 `ScanText` = AI OCR（AI 关闭时不会出现）
- **绿色 `ScanLine` = 本地 OCR**（任何时候都在）

点绿色的那个。

### 第 4 步：等首次下载（**这里最容易以为卡死了**）

**预期看到**绿色进度条，依次是「正在加载本地 OCR 引擎」→「正在下载语言包（仅首次）」→「正在初始化识别引擎」→「正在识别图片文字」→「识别完成」。

- **首次加载大小**：引擎约 3–5MB（WASM）+ 简体中文约 12MB + 英文约 4MB ≈ **20MB**。
- **缓存策略**：下载后写入浏览器的 IndexedDB / Cache Storage。之后再用**不用重新下载，甚至可以离线识别**。清除浏览器数据、换设备、换浏览器会重新下载。
- **弱网提示**：弱网可能等 30–60 秒，请**保持页面打开**，不要反复点按钮。超过 120 秒会自动超时并提示，此时**原图仍在**，可以直接手动录题，不影响流程。
- 其他语言（繁中/日/韩/法/德/西）**默认不下载**，在 `/settings` →「OCR 识题设置」里按需勾选，每多一种约 4–14MB，只在第一次用那种语言时下载。语言设置只存在本机浏览器，不跨设备同步。

> `[截图占位：绿色进度条停在「正在下载语言包」]`

### 第 5 步：在预览框里改错字，确认后才写入

识别完会弹出「**OCR 识别结果（可直接修改，确认后才填入）**」，标题旁标着「**本地 OCR（离线免费 · 未调用 AI）**」。
这个框是**可以编辑的文本框**，不是只读的：

1. 把识别错的字直接改掉（本地 OCR 对公式、手写、竖排文字容易错）。
2. 觉得不对可以不填，点「放弃」，原图还在。
3. 点「**填入题目正文**」→ 文字进入富文本编辑区。
4. **还要再点一次「保存到云端」**才会真正写进数据库。

> ⚠️ 本地 OCR **不会生成 LaTeX 公式**，只把公式识别成普通文字（例如 `x^2`）。需要漂亮公式请手动输入 KaTeX，或开启 AI 后用 AI OCR。

### 第 6 步：怎么确认「真的没花钱」

按 `F12` → 切到 `Network`（网络）→ 在过滤框输入 `ai` → 再做一次本地识别。
**预期**：列表里**没有任何 `/api/ai/*` 请求，也没有 dashscope 请求**；只可能看到语言包 CDN 的下载（那是程序文件）。设置页「累计成功调用」数字也不会增加。

### 识别不准 / 失败怎么办

| 情况 | 怎么办 |
| --- | --- |
| 识别出一堆乱码 | 换更清晰的图、把图裁到只剩题目、避免反光和倾斜；改完直接在预览框里修正 |
| 数学公式全乱 | 正常，本地 OCR 不做公式还原；手动输入 KaTeX 或开 AI OCR |
| 一直卡在下载语言包 | 检查网络能否访问公共 CDN；弱网等 30–60 秒；换 Chrome / Edge 试试；清了浏览器缓存会重新下载 |
| 提示超时 / 报错 | **原图不会丢**，直接在题目正文里手动打字即可，不阻塞录题 |
| 想更准 | `/settings` 打开 AI 总开关（以及 `OCR/图片识题` 子开关）→ 用蓝色 AI OCR 按钮 |

### ✅ 6.3 阶段三句话

- **这个阶段我要做什么**：关掉 AI → 上传一张有字的图 → 点绿色扫描线 → 等首次下载 → 改错字 → 填入并保存 → F12 看有没有 AI 请求。
- **怎么验证成功**：文字能进题干、原图还在、Network 里没有 `/api/ai/*`。
- **下一步该对我说什么**：`本地 OCR 在 AI 关闭时可用，Network 无 AI 请求` 或 `本地 OCR 卡在下载语言包：[截图 + Console 报错]`。

## 6.4 习惯补打卡、取消打卡、连续天数怎么算

### 第 1 步：先建一个习惯并记下当前数字

`/habits` → 在「新习惯名称」填「背 20 个单词」→ 点「创建习惯」→ 看顶部三张卡片里的「最长连续天数」（现在多半是 0）。

### 第 2 步：点「补打卡」

页面右上角有「**补打卡**」按钮，点开后出现一块面板：习惯、补录日期、备注，以及「昨天 / 前天 / 7 天前 / 30 天前」四个快捷按钮。

- 点「**昨天**」→ 日期自动填好。
- 点「**前天**」→ 再补一天。
- 也可以点日期框，选**任意过去日期**（不能选未来，选了会提示「不能给未来日期补打卡」）。
- 备注可留空，例如写「补记忘打的」。

### 第 3 步：二次确认（每次都有）

点「**下一步（二次确认）**」→ 弹窗：

- 这天没打过卡：标题是「**确认补录 2026-11-07 的打卡？**」，说明补录会立即重算统计。
- 这天已经打过卡：标题是「**2026-11-07 已打卡，是否修改？**」，说明只会更新备注，**不会新增第二条**。

点确认才真正写入。

### 第 4 步：看统计有没有「实时」变

**预期（不用刷新页面）**：

- 「最长连续天数」增加；
- 月视图里那天出现一个带颜色的小圆点；
- 「本月打卡次数」增加；
- 首页仪表盘、目标页里引用习惯进度的地方也会跟着变（下次打开时读取的是同一份全量数据）。

### 第 5 步：取消某天打卡

在月视图找到那一天 → 圆点旁边有个红色的「**×**」→ 点它 → 弹「取消 2026-11-07 的打卡？」→ 二次确认 → 删除。
**预期**：连续天数、月视图、KPI 立刻回退。
⚠️ 打卡记录**不进回收站**（删除后想恢复就再补录一次），所以这一步特意做了二次确认。

### 连续天数到底怎么算？（补录后统计为什么变）

```
从「今天」开始往回一天一天数：
  如果今天打过卡 → 从今天算第 1 天，再检查昨天、前天……
  如果今天还没打卡 → 从昨天开始算（今天不算断）
  遇到任何一天没打卡 → 立刻停止
  最多往回数 730 天
```

所以：

- **补「昨天」通常会让连续天数 +1**（前提是前天、大前天也连着）；
- **补一个中间断开的日期，可能把两段连续合并**，连续天数一下涨很多；
- **补很久以前但中间有空档的日期，连续天数不变**（因为数到那个空档就停了），但「本月/历史打卡次数」和月视图圆点还是会变。这是正常现象，不是 bug。

**重算范围与性能影响（如实说明）**：
补录或取消后，前端会**重新拉取你这个账号的全部打卡记录**（不再是只查当月，否则补上个月不生效），然后一次性重算连续天数、月视图、KPI。个人使用通常几百到几千行，一次查询、毫秒级完成，不需要手动刷新。数据库已有「同一天同一习惯唯一」约束和按日期索引；如果日志超过 5000 行，可能需要另建索引或按年分段加载，本次版本**没有做分页**，属于已知限制。

### ✅ 6.4 阶段三句话

- **这个阶段我要做什么**：补昨天、补前天、补一个任意过去日期 → 重复补同一天看提示 → 取消一天看回退。
- **怎么验证成功**：数字不刷新就变；重复补录提示「已打卡，是否修改」；取消后立刻回退。
- **下一步该对我说什么**：`补录与取消都验过了，统计实时更新` 或 `补录后连续天数没变：[补录前后截图]`。

## 6.5 AI 开关与费用保护（补完功能视角）

前面第五部分 5.11 已经完整讲过 AI 总开关/子开关，这里只补这次新增的部分：

- **Word / Anki 导出、本地 OCR、习惯补录这 4 项完全不走 AI**：它们既不在 `/api/ai/*` 下面，也不读 Coding Plan Key。关掉 AI 总开关、甚至 Key 一个都不填，功能照常，费用为 0。
- **关闭 AI 后本地 OCR 自动成为唯一的 OCR 通道**：图片上的蓝色 AI OCR 按钮隐藏，绿色本地 OCR 按钮始终可用；设置页「OCR 识题设置」里明确写了「本区域不受 AI 总开关控制，也不会产生任何 AI 调用和费用」。
- **未配置 Key 时**：设置页提示「AI未配置」，页面不白屏；导出、本地 OCR、补打卡、打印、复习、统计全部正常。
- **想确认零费用**：关总开关 → F12 Network 过滤 `ai` → 做一次本地 OCR 和一次 Word 导出 → 应看到 0 个 AI 请求；设置页「累计成功调用」不增加；阿里云 Coding Plan 控制台用量不涨。
- **重新开启 AI**：`/settings` 打开总开关即可，**不需要重新部署**；本地 OCR 与 AI OCR 可以同时存在，互不影响。
- **改了环境变量（Key / Base URL / 模型）才需要 Redeploy**，只拨开关不用。

## 6.6 维护与排错（补完功能专用）

### 6.6.1 Word 打不开 / 图片不显示

| 现象 | 排查顺序 |
| --- | --- |
| 双击提示「文件已损坏」 | ① 看下载是否完成（文件大小是不是 0KB）；② 重新导出一次；③ 换 Word / WPS / LibreOffice 打开；④ 看 Vercel → Functions Logs 里 `/api/export/word` 有没有报错 |
| 打开后图片是空白框 | 服务端缺 `sharp`（WebP 转 PNG 组件）。看导出时页面有没有黄色提示框；Vercel 重新部署一次让依赖装齐；`node scripts/verify-export.mjs` 应全 OK |
| 图片变成一串网址 | 理论上不会发生（我们用的是内嵌不是链接）。把截图发我，我按 `lib/export/word` 排查 |
| 公式显示为 `$...$` 文本 | 正常：Word 导出把公式保留成文字，不渲染 KaTeX。需要漂亮公式请在 Word 里手动改 |
| 导出时红色 toast「导出失败」 | 把报错文字发我；常见是没登录（提示「请先登录后再导出」）、筛选结果为空、图片太大被跳过 |

### 6.6.2 Anki 图片丢失 / 导入失败

| 现象 | 排查顺序 |
| --- | --- |
| 卡片上显示 `<img src="m_xxx.png">` 文字 | 导入时**没勾「允许在字段中使用 HTML」**，删掉这批重新导入并勾上 |
| 卡片上破图标 | ① 确认解压后有 `mistakes.tsv.media` 文件夹并且里面有图；② 按 6.2 第 6 步把图片复制到 `collection.media`；③ 重启 Anki |
| 只有一列 / 字段全挤在一起 | 分隔符选错了：TSV 选 `Tab`，CSV 选 `逗号` |
| 第一张卡片不见了 | 误勾了「忽略第一行」，重新导入时不要勾 |
| 导入 0 张 | 看导入对话框的「字段对应」是不是 Front/Back；看 zip 里 `mistakes.tsv` 有没有内容（用记事本打开） |
| Anki 手机版导入 | 建议先用桌面版导入再同步到手机；手机端对文本+媒体包的支持不如桌面版 |

### 6.6.3 本地 OCR 慢 / 失败

见 6.3 末尾的「识别不准 / 失败怎么办」表格。补两条：

- **完全内网 / 断网且从没用过本地 OCR**：引擎和语言包没下载过，会超时。这是已知限制：本次没有把语言包自托管到项目里（体积约 20MB）。需要彻底内网使用时，把「本地 OCR」当成不可用，用手动录入；或让我后续加自托管语言包。
- **换设备后第一次又慢**：正常，语言包缓存是按浏览器/设备存的。

### 6.6.4 导出 / 补录的其他问题

| 现象 | 原因与处理 |
| --- | --- |
| 导出按钮点了 404 | 新代码没部署到 Vercel；看 Deployments 状态 |
| 未登录 curl 导出接口返回「请先登录后再导出」 | **正常且必须如此**：导出走 RLS，只能导出自己的数据 |
| 黄色提示「图片数量超过 40 张」 | 单次上限；缩小筛选范围分两次导出，原图不丢 |
| 补录后统计没变 | 看 6.4「连续天数怎么算」：补的日期不在连续链上就不会加连续天数，但月视图和次数仍会变 |
| 重复补录出现两条 | 理论上被数据库唯一约束挡住；若真出现，把 `habit_logs` 截图发我，并跑 `supabase/selfcheck.sql` 第 9 项 |
| 更新代码后这些功能没了 | 重新推 GitHub 等 Vercel 自动部署；改环境变量才需要手动 Redeploy |

### 6.6.5 怎么更新代码 / 换 Key（和以前一样）

## 6.8 常见问题 FAQ

**Q：AI 关了，导出 Word / Anki 还能用吗？**
A：能。它们只读数据库和私有图片桶，完全不经过 AI。

**Q：Word 文件发给同学，他没登录网站能看到图吗？**
A：能，图片在文件里。但**注意隐私**：导出的是你自己的错题，发给别人前想清楚。

**Q：Anki 为什么不给我 `.apkg`？**
A：`.apkg` 需要构造 Anki 内部的 SQLite 数据库和媒体映射，实现成本高且易出错。所以本次**明确降级**为 Anki 官方同样支持的 TSV/CSV + 媒体包，功能上一样能导入、图片一样能带，只是多一步「解压 + 字段对应」。限制已同步写进 `docs/04` VI2 和 `docs/03` V5.4。

**Q：Anki 图片会不会换电脑就丢？**
A：导入成功后不会——图片会被复制进 Anki 自己的 `collection.media`，跟着 Anki 同步走。**只有 zip 没完整解压、或导入时没勾 HTML，才会看起来像丢图**。

**Q：本地 OCR 会把我的照片传到阿里云吗？**
A：不会。识别在浏览器 Worker 里跑，图片从不上传。首次下载的是识别引擎和字典文件（从 CDN 下载到本机），不是上传。

**Q：本地 OCR 能识别手写和公式吗？**
A：手写体勉强，公式只能给文字、不生成 LaTeX。要准就开 AI 用 AI OCR，或手动输入。

**Q：补打卡会让「连续天数」一下变很多，是 bug 吗？**
A：不是。补上中间断开的那一天会把两段连续合并，算法见 6.4。

**Q：改了 AI 开关要重新部署吗？**
A：不用，开关存在云端用户设置表里，换设备也同步。**只有改环境变量才需要 Redeploy**。

**Q：这些功能助手都测过了吗？**
A：**没有真实联调**。编译和构建是本地真跑过的，导出技术链用 `verify-export.mjs` 真验证过，但 Word/Anki/真机 OCR/跨设备同步必须你按 `docs/08` 验。这是如实说明，不是"已支持"四个字能代替的。

## 7.0 先用大白话讲清楚：图片存在哪

以前你可能会担心「图片是不是存在我电脑里，电脑一关网站就没图了」。现在**明确不会**：

| 东西 | 存在哪 | 会不会因为关电脑丢 |
| --- | --- | --- |
| 图片本体 | **云端的 Supabase Storage（一个私有网盘）** | ❌ 不会。手机、电脑、任何网络登录同一账号都能看 |
| 数据库里 | **只有一行字**：图片在网盘里的路径 + 宽度高度大小等元数据 | ❌ 不会，而且数据库里**一张图片数据都没有**（没有 Base64、没有二进制） |
| 你电脑/U 盘里的 zip | 只是你**手动下载的离线副本** | 网站**完全不读它**，删了也不影响网站 |

一句话：**网页取图只认云端网盘，不认你电脑**。换电脑、重装系统、把电脑关了，图片照样在。

【截图占位：新建错题页顶部绿色「拍照 / 上传整题」按钮，旁边是普通「插入图片」区域】

| 入口 | 用在哪 | 会发生什么 |
| --- | --- | --- |
| **拍照 / 上传整题**（页面顶部绿色按钮） | 拍一整张试卷、一整道大题 | 整图单独存成「整题原图」，自动尝试 OCR，出来一个**预览工作区**，你确认后文字才进题干 |
| **插入图片**（下面的普通图片区） | 往题目里补一张小图 | 按老办法压缩上传，作为普通插图，不会触发整题 OCR |

## 7.1 阶段 G：整题拍照上传（最常用）

### 第 1 步：打开新建错题页

在网站点「错题本 → 新建错题」，或直接打开 `/mistakes/new`。

**怎么验证成功**：页面最上面能看到一个**绿色**的「拍照 / 上传整题」按钮。
【截图占位：顶部操作条，绿色按钮在「保存到云端」左边】

> ⚠️ 易错提醒：不要用下面「插入图片」里的「拍照」按钮来做整题录入，两个入口不一样。

### 第 2 步：拍照或选截图

点绿色按钮 → 弹出「整题录入预览」→ 点里面的「拍照上传整题」（手机会打开相机）或「相册 / 截图（可多张）」。

一次最多选 **9 张**。选完会自动开始：

1. 浏览器先把照片压小（最长边 1600 像素、WebP 格式、质量 0.8，一般压到 200–500KB）；
2. 压好的图传到云端私有网盘；
3. 数据库写一行记录，标记「这张是整题原图」；
4. 然后才可能触发 OCR。

**怎么验证成功**：看到进度条走完，并提示「N 张整题原图已上传到云端」；预览工作区右边能看到刚拍的图。
【截图占位：预览工作区，左边是可编辑文字框，右边是整题原图，上方有缩放/旋转按钮】

> ⚠️ 易错提醒：如果提示「图片上传失败…未写入任何数据库记录」，说明**没传上去，也没有留下空记录**，直接重试即可，不会产生脏数据。HEIC 格式（iPhone 原生）如果浏览器解不了，会提示你先在手机上转成 JPG/PNG，原图不会被删。

### 第 3 步：看「预计调用次数」这一栏

上传后，预览工作区上方有一行彩色提示：

- **绿色**：`AI OCR 已开启：本批预计调用 N 次`。每张整题图算 1 次；同一张图识别过会命中缓存，不再重复扣费；失败最多重试 1 次。
- **黄色**：`OCR 不可用（AI功能已关闭 / AI未配置 / OCR识题已关闭）：预计 AI 调用 0 次`。这时**不会发任何 AI 请求，不会产生任何费用**，整题原图照样上传保留。

**怎么验证成功**：关闭 AI 总开关后上传一张整题图，浏览器按 F12 → Network（网络）里**看不到任何 `/api/ai/...` 请求**。

> 这个自动触发有**四个条件同时满足**才会发生：AI 总开关开、OCR 子开关开、服务端配好了 `DASHSCOPE_CODING_API_KEY`、配好了 `AI_BASE_URL`。少一个都不调用。

### 第 4 步：核对并修改 OCR 文字（重要）

识别出的文字**不会自动写进题目**，它先躺在左边的可编辑框里。你要：

1. 对照右边的原图，把识别错的字改掉；
2. 选项、公式分别在下面两个输入框里改；
3. 如果 AI 给了一段「图形描述」，那一段会标着 **「AI 描述，仅供参考」**——它只是参考，**不能替代原图**，打印默认也不打印它。

右边原图可以点 `＋/－` 放大缩小、点旋转按钮转 90°，方便你核对。

【截图占位：左侧三个输入框（题干/选项/公式）、右侧放大到 150% 的原图、黄色 AI 描述提示框】

### 第 5 步：选择怎么处理

预览工作区最下面有一排勾选项：

| 选项 | 说明 |
| --- | --- |
| ☑ 文字写入 | 不勾就只留原图、不写文字 |
| ○ 题干 / ○ 解析 | 选文字写到哪里（默认题干） |
| ☑ **整图作为附件保留（锁定，不能取消）** | 这是硬规则：**整题原图永远保留**，放弃 OCR 也不会丢 |
| ☐ 写入 AI 图形描述 | 默认不勾；勾了会写进正文并强制带「AI 描述，仅供参考」标注 |
| 「手动裁剪一块区域」 | 在第 6 步讲 |
| 「放弃 OCR，只留原图」 | 清掉识别文字，原图还在，你可以直接手动录入 |
| 「本地 OCR」 | 浏览器离线识别，中英文，**不联网、不调用 AI、零费用** |

**怎么验证成功**：点「放弃 OCR，只留原图」后，文字框清空但右侧原图仍在。

### 第 6 步：手动裁剪（可选，只做手动框选）

点「手动裁剪一块区域」→ 在图上**按住鼠标拖一个框**（手机用手指拖）→ 点「确认裁剪并上传」。

裁剪图会**单独存一条记录**，来源指向整图，原整图**不会被删除或改动**。裁剪成功后，回到编辑页会出现「手动裁剪图」小图，可点「插入题干」。

**限制（必须知道）**：

- 只支持**你自己手动框选**；**AI 不会自动从整张试卷里把几何图切出来**（视觉模型做不到精确图像分割），这是明确的降级，不是遗漏。
- 想用 AI 重画几何图？本项目**没有做**；就算以后做，也只能标注「AI 生成示意图，非原题图」当装饰，不能替代原图，打印默认不用。
- 裁剪失败或点取消，**原图和已经写好的文字都不受影响**。

### 第 7 步：确认应用，再保存

点「确认应用」→ 文字进入题干编辑区、整图挂到这道题上 → 回到编辑页后**再点「保存到云端」**才算真正写进数据库。

**怎么验证成功**：打开 `/mistakes/这条错题`，能看到绿色「整题原图」区块，标注清楚；题干里有你确认过的文字。

> ⚠️ 易错提醒：整题预览里的「确认应用」≠ 保存。忘记点「保存到云端」关掉页面，图已经在云端（可在回收站/孤儿清理里找到），但文字可能只在草稿里。

## 7.2 阶段 H：AI 关闭时怎么识题（零费用）

### 第 1 步：确认 AI 是关的

设置页（`/settings`）看「AI功能当前状态：已关闭」。没配 Key 时会显示「AI未配置」，同样自动禁用 AI 入口。

### 第 2 步：照样上传整题图

按 7.1 的第 1–2 步做。上传**完全不受影响**，因为图片上传不属于 AI 功能。

### 第 3 步：点「本地 OCR」或手动输入

预览工作区会出现黄色提示「OCR 不可用…预计 AI 调用 0 次」。这时：

- 点「**本地 OCR**」：浏览器自己识别中英文，**图片不上传到任何外部服务**；
- 或者干脆在左边文字框**手动打字**。

识别结果同样先预览、确认后才写入，跟 AI OCR 一模一样。

**怎么验证成功**：F12 → Network 里**没有任何 `/api/ai/*` 请求**；设置页用量记录没有新增；原图仍在。

### 本地 OCR 的已知限制（如实说明）

| 限制 | 说明 |
| --- | --- |
| 语言 | 默认**简体中文 + 英文**；繁中/日/韩/法/德/西在设置页按需勾选，每种约 4–14MB |
| 首次加载 | 约 **16MB 语言包 + 3–5MB 引擎**，弱网可能等 30–60 秒；下载后缓存在浏览器 IndexedDB，之后可离线用 |
| 弱网 | 超过 120 秒会超时，原图保留，可直接手动录入，不阻塞录题 |
| 公式 | **只输出纯文本，不生成 LaTeX**；要精确公式请用 AI OCR（开启时）或手动写 `$...$` |
| 语言包来源 | 走公网 CDN，**没有自托管**；完全隔离公网的内网环境不可用 |
| 处理范围 | 只处理**你当前上传的这张图**，不会去读你电脑里的历史文件 |

> **不会因为慢就偷偷改回外部 AI**：本地 OCR 全程在浏览器里跑，代码里没有任何 AI 请求。

## 7.3 阶段 I：本地原图备份（可选，不是主方案）

### 第 1 步：想清楚要不要

JSON 备份里只有图片路径，**不含图片本体**。想自己也存一份图片，就做这一步。不做也完全不影响网站使用。

### 第 2 步：打开设置页备份区

`/settings` → 「备份与恢复」→ 找到绿色框「本地原图备份」。

可以选**错题本**或**时间范围**（不选就是全部），点「导出原图包（zip）」。

【截图占位：设置页备份区，绿色框里有错题本下拉、起止日期、导出原图包按钮和进度文字】

### 第 3 步：解压查看

下载的 zip 里有：

```
images/     所有图片（整题原图、裁剪图、普通插图）
清单.txt    每张图 → 对应哪道错题、什么用途、云端路径
说明.txt    这个包是什么、换电脑会不会丢图
```

**怎么验证成功**：zip 能解压，图片能打开，`清单.txt` 里能找到你熟悉的一道错题名字。

### 必须知道的三件事

1. **这是离线副本，网页不读它**。换电脑、重装系统、把这个 zip 删了，网站里的图**一张都不会少**——网站永远从云端 Storage 取图。
2. **包里是「压缩后的展示图」，不是手机相册里的原始未压缩照片**。因为拍照后浏览器先压成 200–500KB 的 WebP 才上传，云端本来就没有未压缩原文件。想留原始照片，请自己在相册/电脑里另存。
3. **不做自动同步、不读你电脑文件夹**。浏览器安全限制也不允许网页实时读本地目录，那样手机上就没法用了。

> 单次上限 300 道 / 500 张 / 60MB，超了会提示缩小范围分批导出；失败会给出具体提示，不会静默丢图。

## 7.7 FAQ

**Q：我把电脑关了，手机还能看到图片吗？**
能。图片只存在云端私有网盘，网页不读你电脑。

**Q：数据库里到底有没有图片？**
没有。只有一行路径 + 元数据（宽高、大小、用途、是否已本地备份）。没有 Base64、没有二进制、没有 Blob。

**Q：「整题原图」会被 OCR 覆盖吗？**
不会。OCR 文字和原图是两条独立记录，改题干不影响原图；删除原图要二次确认，还会提示有没有裁剪图。

**Q：AI 关了，整题上传还能用吗？**
能。原图照常上传保留，只是不自动 OCR；可以用本地 OCR 或手动录入，零费用。

**Q：AI 会自动把整张试卷里的几何图切出来吗？**
不会，这是明确不做的。只支持你手动框选裁剪。

**Q：本地原图包删了，网站的图会没吗？**
不会。那只是离线副本。

**Q：为什么原图包里的图比手机相册里的小？**
因为拍照后浏览器先压缩（200–500KB WebP）再上传，云端没有未压缩原文件。想留原始照片请自己在相册另存。

**Q：分享链接过期后，别人还能看到图片吗？**
不能。分享页的签名 URL 有效期不会超过链接剩余时间，链接过期图片也 404。

# 第八部分 · v5 课本管理与「按科目课本组卷」教学

## 8.0 先搞清楚一件事：AI 不会帮你搜课本

本项目接入的**阿里云百炼 Coding Plan 只有 Chat/Completions，没有联网搜索能力**。所以：

- 网站里**没有**、也不会有「输入课本名称，AI 自动搜到课本并出题」这种功能；
- 你能抽到的题，永远来自**你自己录进系统的真实错题**，以及你维护的「章节 ↔ 知识点 / 错题」映射；
- AI 补充出题时，唯一依据是**你上传的课本材料（含 OCR 文字）或你填写的章节内容摘要**。材料不足时它会明确告诉你「缺什么」，**不会编题**。

一句话：课本由你建、目录由你贴、材料由你传、映射由你连；AI 只在这个范围内做文字加工。

## 8.1 第 1 步 · 新建课本

1. 顶部导航点「课本」（或打开 `/textbooks`）。
2. 点「新建课本」，填写：课本名称（必填）、科目、出版社、版本、年级、册次、备注；封面图可选，选了会压缩后上传。
3. 版本**由你手填/手选**（如「2019 人教A版」）。系统不会自动识别版本，这是故意的：自动识别容易匹配错册次。
4. 保存后列表页可按科目、年级、版本筛选。

## 8.2 第 2 步 · 建章节树（两种方式）

**方式 A：粘贴目录（推荐）**

点「粘贴目录批量导入」，把课本目录粘进去，例如：

```
第一章 集合
1.1 集合的概念
1.2 集合间的基本关系
第二章 函数
2.1 函数的概念
2.2 函数的单调性
```

预览区会标出哪些是「章」、哪些是「节」，确认条数后点「确认导入」。目录里的点线和页码（`........ 3`）会被自动去掉。

**方式 B：手动新增**：点「新增章」，再在章右侧的「+」新增节。章节树**严格两级**（章 → 节），不支持三级。

**排序**：拖动章标题可在章之间排序；拖动节标题可在同一章下排序。跨层级拖动会被拒绝并提示。

> ⚠️ **整本 PDF 自动解析成章节树未实现**。原因：Coding Plan 不具备整本 PDF 结构化解析能力，自动切出来的章节无法验证，容易版本/章节错配。请粘贴目录或手动录入，只把需要的**片段**上传。

## 8.3 第 3 步 · 给章节补「真实材料」

点左侧某个章节，右侧可以：

| 操作 | 说明 |
| --- | --- |
| 填章节内容摘要 | 把课本里的定义、公式、例题文字粘进来（建议 ≥10 字）。它本身就是 AI 出题的可信材料 |
| 上传图片 | 选图 → 浏览器压缩 → 私有桶 Storage → 数据库只记路径 |
| 上传 PDF 片段 | 只传需要的几页，≤20MB |
| 填 OCR 文本 | 把图片/PDF 里的正文文字粘进来；**纯图片没有文字时，AI 会判为材料不足** |
| 直接录入文字材料 | 不上传文件，直接粘正文/例题文字 |
| 删除材料 | 软删除进统一回收站，Storage 文件在彻底删除时才物理删掉 |

章节右上角的状态标签会显示「已有真实课本材料 / 尚无可用课本材料」，下面还会分别列出摘要、文字材料、文件是否具备。

## 8.4 第 4 步 · 关联知识点与错题（决定「抽什么题」）

- **知识点映射**：在章节详情添加知识点，例如「集合的包含关系」。错题的 `knowledge_points` 或标签命中这些词，就会被**间接**抽进该章节的卷子。权重目前用于间接命中题的排序。
- **直接关联错题**：搜索错题标题/内容 → 点「关联」。这些题会被**优先**抽中。
- 两种关联都由你维护；错题本身不会被改动或删除。

## 8.5 第 5 步 · 按「科目 → 课本 → 章节」组卷

1. 打开 `/review/random`，把模式切到「**按科目课本组卷**」（原来的「按条件随机组卷」原样保留）。
2. 依次选：科目 → 课本 → 章节。章节选择器可搜索标题、可全选、可只选章或只选某几个节；手机上也可用。选「章」会自动包含其下所有节。
3. 设置题量（1–50）、难度下限/上限、是否「只抽未掌握 / 错过的题」。
4. 点「按章节抽题（真实错题）」。抽题优先级：
   - ① 直接关联到所选章节的错题；
   - ② 知识点/标签命中章节映射的错题；
   - ③ 还不够时，才提示「错题不足 N 道，是否用 AI 补充」。
5. 结果页每题都显示「**来源章节**」列和「**真实错题**」标签，并标出是直接关联还是知识点命中；「显示答案」、重练结果标记、打印仍走原来的链路。
6. 点「保存为模板」可把这次配置存下来，下次在已存模板里点一下即可复用。

## 8.6 第 6 步 · AI 补充出题（可选，四道门槛）

必须先全部满足，按钮才可用：

1. `/settings` 打开 **AI 总开关**；
2. 打开 **「课本AI补充出题」** 子开关（`ai_textbook_quiz`，默认关闭，跨设备同步）；
3. 服务端已配置 `DASHSCOPE_CODING_API_KEY` 与 `AI_BASE_URL`（设置页会显示「AI未配置 / 已关闭 / 已开启」）；
4. 目标章节有课本材料（含 OCR 文字）或章节内容摘要。

流程：错题不足提示卡片 → 选「目标章节」→ 点「AI 补充出题」→ 二次确认（会消耗 Coding Plan 配额）→ 得到候选题。

**候选题不是最终结果**：它们标着「AI生成，需核对，可能偏离课本」，你可以逐题勾选确认、编辑、删除、单题重新生成；只有点「把已确认的题加入组卷结果」才会进本卷。

**AI 题的三条红线**：默认不进打印（要手动勾选「加入学生版打印」）、不写入错题库、不参与后续随机抽题。服务端提示词明确要求「仅基于以下课本材料出题，不得引入材料之外的内容；材料不足返回原因，不要编造」。

## 8.7 第 7 步 · 打印与回收站

- 打印仍走 `/print`：学生版 / 答案版 / 复习版模板**没变**。只有你手动勾选过的 AI 题才会出现在打印页，而且题面自带「AI生成，需核对，可能偏离课本」标注。
- 删除课本 / 章节 / 材料都进 `/trash` 统一回收站，**30 天内可恢复**。删除课本前会二次确认，并明确列出影响范围：章节数、材料数、知识点映射数、错题关联数；错题本身不会被删除。恢复课本时章节与材料一起回来。

## 8.8 常见问题与排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 「AI 补充出题」按钮是灰的 | 依次看：AI 总开关、`ai_textbook_quiz` 子开关、服务端 Key/Base URL、目标章节材料状态。四者缺一不可 |
| 提示「课本材料不足，未生成任何题目」 | 服务端 `422 INSUFFICIENT_MATERIAL`：没材料/没摘要，或图片没有 OCR 文字。到章节详情补文字，这是设计行为，不是故障 |
| 「AI功能已关闭 / 课本AI补充出题已关闭」 | 服务端 `403`，请求在发起任何上游调用之前就被拒绝，零费用。按课本抽真实错题不受影响 |
| 429 / 超时 / 模型报错 | 限流、超时、上游错误都有中文提示，不会白屏，也不会偷偷改用「编题」兜底；稍后重试或看设置页用量 |
| 上传 PDF 报 415 | 桶的 MIME 白名单没更新：SQL 更新 `storage.buckets` 可能触发 `42501`（迁移里已有异常保护，不会中断整份脚本）。到 Supabase → Storage → `mistake-images` → Configuration → Allowed MIME types **手动加 `application/pdf`** → `Save`。图片上传不受影响 |
| 课本页报表不存在 | 没执行迁移 SQL |
| 备份里能看到课本数据，恢复却没有 | **课本模块自动恢复未实现**：6 张表已导出，但关联 id 需要重新映射。请用「粘贴目录导入章节」重建章节树，再重新关联知识点与错题 |

## 8.9 明确不做的事

1. AI 联网搜索课本 —— 技术上做不到，也不允许假装做到。
2. AI 自动识别课本版本并匹配 —— 版本由用户选择。
3. AI 把整本 PDF 解析成章节树 —— 未实现，原因见 8.2。
4. AI 生成题自动写入错题库 —— 不做；当前版本也没有「收录为错题」入口。
