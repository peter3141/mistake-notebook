## 2. 模块结构（合并后共 10 个模块）

```
个人综合管理网站
├─ ① 错题本（v1 全部功能，保持不变）
├─ ② 日程管理        ← 新增
├─ ③ 待办任务        ← 新增
├─ ④ 笔记            ← 新增
├─ ⑤ 习惯打卡        ← 新增
├─ ⑥ 番茄钟          ← 新增
├─ ⑦ 目标管理        ← 新增
├─ ⑧ 统计仪表盘      ← 由「错题仪表盘」升级为「全站聚合仪表盘」
├─ ⑨ 统一搜索        ← 新增
└─ ⑩ 统一回收站      ← 由「错题回收站」升级
公共底座：账号 / RLS / 图片存储 / 打印 / 备份 / 只读分享 / AI 开关 / PWA
```

### 2.1 新增模块功能规格

| 模块 | 必须支持 |
| --- | --- |
| ② 日程 | 日 / 周 / 月三种视图；创建·编辑·删除；开始结束时间、全天、地点、分类、优先级、提醒、重复规则（无/每天/每周/每月）、完成状态；关联错题 / 笔记 / 待办；按日/周/月打印或导出 PDF；AI 自然语言创建日程（**必须先预览确认再创建**，受总开关 + `ai_schedule_parse` 子开关控制） |
| ③ 待办 | 任务清单、优先级、截止时间、子任务（勾选）、完成状态、筛选排序、重复任务；与日程、番茄钟联动；可从错题复习计划一键生成 |
| ④ 笔记 | 富文本（复用 Tiptap + KaTeX + 表格）、图片、标签、全文搜索、历史版本（可回滚）、只读分享；关联错题与日程；AI 笔记总结（受总开关 + `ai_note_summary` 子开关控制，预览确认后写入） |
| ⑤ 习惯打卡 | 创建习惯、每日打卡、连续天数（streak）、月视图、统计、提醒时间 |
| ⑥ 番茄钟 | 25/5 可配置专注计时、关联待办或错题、专注记录、今日/本周统计、休息提醒 |
| ⑦ 目标管理 | 长期目标、里程碑（勾选）、进度自动计算、关联待办和习惯 |
| ⑧ 统计仪表盘 | 首页聚合：今日日程、今日待办、今日待复习错题、习惯打卡进度、今日专注时长；`/stats` 保留原有错因分布、知识点热力图、新增趋势、复习完成率，并追加习惯/专注/目标概览 |
| ⑨ 统一搜索 | 一次输入跨 **错题、日程、待办、笔记、标签** 搜索，结果按模块分组，点击直达详情 |
| ⑩ 统一回收站 | 错题、笔记、日程、待办、习惯、目标的软删除统一进入，30 天内可恢复，彻底删除/清空均需二次确认 |

### 2.2 模块联动（验收 10 与第 7 段第三节，逐条落地）

1. **错题复习计划 → 日程 / 待办**：复习页与错题详情提供「生成复习日程」「生成复习待办」，把 `next_review_at` 作为时间写入，并带上 `mistake_id` 关联。
2. **日程 → 错题**：日程表单可多选关联错题；日程卡片与详情显示关联错题，点击跳 `/mistakes/[id]`。
3. **番茄钟 → 待办 / 错题**：开始专注时选择关联对象；结束写入 `focus_sessions(task_id | mistake_id)`，统计页按对象汇总。
4. **目标 → 待办 / 习惯**：目标关联若干待办与习惯，进度 = 里程碑完成率 + 关联任务完成率的加权展示。
5. **首页仪表盘**：必须同屏展示上述 5 类今日数据（缺数据也显示 0 卡片，不白屏）。
6. **统一搜索**：覆盖 5 类对象，结果按模块分组。

> `ai_jobs.kind` 检查约束放宽为 `organize | ocr | similar | batch | schedule | note | plan`，让新增 AI 能力同样享受缓存 / 任务状态 / 用量记录 / 重试上限保护。
> `share_links.scope` 放宽为 `single | book | filter | note | schedule`，分享页隐藏编辑按钮与隐私字段的规则不变。

### 4.3 安全模型（不变 + 扩展）

- 全部 30 张表启用 RLS，`using (auth.uid() = user_id)`（profiles 用 `id`），`with check` 同样校验；未登录 anon 无策略 = 完全不可访问。
- 私有 Storage 桶 `mistake-images` 继续按 `(storage.foldername(name))[1] = auth.uid()::text` 四条策略；笔记图片等通用附件沿用同一桶与同一路径前缀。
- 分享页仍**唯一**通过 service_role 白名单字段读取，且校验 token / 过期 / 撤销。
- 统一回收站的恢复/彻底删除通过 `security definer` 函数执行，函数内部**白名单表名 + `auth.uid()` 二次过滤**，杜绝越权与注入。

### 5.1 AI 开关矩阵（扩展后，验收 16–22 + 第 7 段第六节）

| 能力 | 子开关键 | 对应路由 | 关闭后 |
| --- | --- | --- | --- |
| 总开关 | `ai_enabled` | 全部 `/api/ai/*` | **服务端 403「AI功能已关闭」**，零调用零费用；所有入口隐藏/置灰 |
| AI 整理错题 | `ai_organize` | `/api/ai/organize` | 入口置灰 + 路由拒绝 |
| OCR / 图片识题 | `ai_ocr` | `/api/ai/ocr` | 同上（原图保留、手动录入不阻塞） |
| 相似题推荐 | `ai_similar` | `/api/ai/similar` | 区域显示「AI功能已关闭」，不报错 |
| AI 批量整理 | `ai_batch` | `/api/ai/organize` (batch) | 批量入口隐藏，不排队 |
| **AI 日程解析** | `ai_schedule_parse` | `/api/ai/schedule-parse` | 自然语言建日程入口置灰；手动建日程完全正常 |
| **AI 笔记总结** | `ai_note_summary` | `/api/ai/note-summary` | 总结入口置灰；手动编辑笔记完全正常 |
| **AI 规划** | `ai_plan` | `/api/ai/plan`（预留，默认关） | 预留位，不产生调用 |

- 判定顺序恒为：**登录 → 总开关 → 子开关 → 服务端配置 → 限流 → 缓存 → 外部调用**。所有判定都在 `fetch Coding Plan` 之前，因此关闭后 100% 无费用。
- 状态存 `user_settings`，跨设备同步；刷新、重登、换设备一致；「恢复默认」一键复位；重新开启**不需要重新部署**。
- 未配置 `DASHSCOPE_CODING_API_KEY` 或 `AI_BASE_URL`：设置页显示「AI未配置」并列出缺失项，自动禁用全部 AI 入口；手动录入/编辑/图片/富文本/筛选/复习/手动组卷/打印/导出/回收站/备份/统计全部正常，不白屏。
- 设置页显示「AI功能当前状态：已开启/已关闭」与当前文本/视觉/OCR 模型名、Base URL、累计调用量（**永不显示 Key**）。

### 5.2 Coding Plan 接入（一字不改，继续有效）

`AI_BASE_URL=https://coding.dashscope.aliyuncs.com/v1`；只走 `/chat/completions`，**禁用 Responses API**；禁用 `maas.aliyuncs.com`、`compatible-mode/v1` 通用端点；`DASHSCOPE_CODING_API_KEY` 且必须 `sk-sp-` 开头；文本模型 `qwen3.7-plus` / `qwen3.6-plus` / `glm-5` / `MiniMax-M2.5`；视觉与 OCR 用 `qwen3.7-plus` / `qwen3.6-plus` / `kimi-k2.5`；模型 ID 精确、区分大小写、无空格。新增的日程解析与笔记总结是**纯文本任务**，用 `AI_MODEL`（文本模型），不调用视觉模型。
