### 1.2 AI 开关字段（重点）

```sql
user_settings
  ai_enabled   boolean default false   -- 总开关：默认关闭 = 零 AI 调用 / 零费用
  ai_organize  boolean default true    -- 子开关：/api/ai/organize
  ai_ocr       boolean default true    -- 子开关：/api/ai/ocr
  ai_similar   boolean default true    -- 子开关：/api/ai/similar
  ai_batch     boolean default true    -- 子开关：批量整理
  ai_text_model / ai_vision_model      -- 设置页展示用
```

- 存在数据库 → 刷新 / 重新登录 / 换设备读取到的是同一行，天然跨设备同步（验收 18）。
- 服务端 `lib/ai/guard.ts` **直接查这张表**判定，不信任前端传参（验收 16）。
- 「恢复默认」= 把上述字段写回默认值，不需要改代码、不需要重新部署（验收 21）。

### 1.3 RLS 策略说明

所有表统一：

```sql
alter table public.<表名> enable row level security;
create policy "own_rows" on public.<表名>
  for all to authenticated
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);
```

- `profiles` 主键列是 `id`，脚本自动改用 `auth.uid() = id`。
- `mistake_images` / `mistake_tags` / `review_logs` 等子表也带 `user_id` 冗余列，策略统一，避免通过关联表越权。
- `anon`（未登录）在这 16 张表上**没有任何策略 → 完全不可见**。
- Storage 桶 `mistake-images` 为**私有桶**，路径约定 `<用户ID>/<错题ID>/<文件>.webp`，4 条策略用 `(storage.foldername(name))[1] = auth.uid()::text` 限制只能操作自己目录。
- 只读分享**不通过 anon RLS**，而是 `/api/share/[token]` 用 `SUPABASE_SERVICE_ROLE_KEY` 在服务端校验 token/过期/撤销后，按字段白名单返回脱敏数据。

### 1.4 验证 RLS 真的生效（照抄执行）

```sql
-- ① 16 张表全部 rls = true
select tablename, rowsecurity as rls
from pg_tables where schemaname = 'public' order by tablename;

-- ② 桶是私有（public = false）
select id, public, file_size_limit from storage.buckets where id = 'mistake-images';

-- ③ 策略数量 >= 16
select count(*) from pg_policies where schemaname = 'public';

-- ④ 注册账号后应自动出现一行设置（ai_enabled = false）
select user_id, ai_enabled, ai_organize, ai_ocr, ai_similar, ai_batch from public.user_settings;
```

预期（v4 完整版）：① 输出 **31 行**且 `rls` 全为 `true`；② `public = false`；③ ≥ 16；④ 有一行且 `ai_enabled = f`。
> 📌 本文件是 v1/v2 结构说明，上面的「16 行 / 30 张表」为当时口径；v4 追加 PART IV 后共 **31 张表**。当前自检请以 `supabase/selfcheck.sql`（按 31 判定）为准。
