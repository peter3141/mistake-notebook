## 一、产品定位与核心流程

一个人用的错题本。核心闭环：

```
录入错题 → 编辑文字/插图 → 按时间归类 → AI 整理(可选)
   → 检索筛选 → 复习提醒 → 重练/组卷 → 打印/PDF → 统计薄弱点
```

**最重要的一条设计原则：AI 是可插拔的增强项，不是必需品。**
关掉 AI 总开关后，网站仍然是一个完整可用的错题本：手动录入、图片、公式、筛选、复习、组卷、打印、导出、回收站、统计全部正常，且服务端不会产生任何一次 AI 请求、不产生任何费用。

### 1.1 用户与角色

| 角色 | 说明 |
| --- | --- |
| 登录用户（本人） | 邮箱+密码 / 魔法链接登录，只能看到自己的数据（RLS 强制） |
| 分享访客（未登录） | 只能打开带 token 的只读分享页，看到脱敏后的题目，看不到编辑入口与隐私字段 |
| 匿名访客 | 只能访问 `/login` 和 `/share/[token]`，其余页面跳转登录 |

### 1.3 关键业务规则

1. **AI 结果不落库覆盖原文**：`/api/ai/organize` 只返回 `result_json` 与 `job_id`，前端展示「预览」；只有用户点「确认应用」才由前端发 `PATCH /api/mistakes`（普通数据库写入），并在同一事务链上由数据库触发器写入 `mistake_versions` 快照。回滚 = 读取某版本 snapshot 并写回。
2. **相似题**只作为 `similar_questions` JSON 展示，界面固定带「AI生成，需核对」标记，不进入题目主表、不参与组卷抽题。
3. **回收站**：`UPDATE mistakes SET deleted_at = now()`；列表默认 `deleted_at is null`；清空 = `DELETE ... where deleted_at is not null`（图片由 Storage 级联策略与存储桶清理函数处理）。
4. **复习间隔**：默认 `[1,2,4,7,15,30]` 天；`result='again'` 回到第 1 档并 `error_count+1`；`fuzzy` 保持当前档；`mastered` 进入下一档。
5. **打印**：所有模板共用 `@media print`，题目块 `.print-block { break-inside: avoid; page-break-inside: avoid; }`，图片 `max-width:100%; max-height: 90mm; object-fit: contain;`，`@page { size: A4; margin: 15mm; }`。
6. **离线**：Service Worker 只缓存已访问页面与静态资源；检测到 `navigator.onLine === false` 时所有写操作按钮禁用并提示，恢复在线后显示「网络已恢复，可同步」提示条，不做静默自动覆盖。

## 三、数据模型（16 张表）

```
auth.users (Supabase 内置)
   │
   ├── profiles                 用户资料
   ├── user_settings           ★ AI 总/子开关、模型、复习间隔、提示词模板、默认打印模板
   ├── subjects                科目（多科目、可归档）
   ├── mistake_books           错题本（多本、可归档、可挂科目）
   ├── tags                    标签
   ├── mistakes                错题主表（全部业务字段 + 软删 deleted_at + ai_result + similar_questions）
   │     ├── mistake_images    图片（存 Storage path，不存公开 URL）
   │     ├── mistake_tags      标签关联
   │     ├── mistake_versions  历史版本快照（触发器自动写入）
   │     ├── review_logs       复习记录
   │     ├── practice_logs     重练记录
   │     ├── ai_jobs           AI 任务状态 + 缓存结果(input_hash)
   │     ├── ocr_jobs          OCR 任务
   │     └── share_links       分享目标为单题时
   ├── ai_usage_logs           AI 调用消耗记录
   ├── print_templates         打印模板
   └── share_links             只读分享链接（也可指向错题本/筛选结果）
```

**AI 开关字段（`user_settings`）** —— 验收标准 16–22 的数据基础：

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `ai_enabled` | boolean | `false` | 总开关，默认关闭（成本安全优先，由用户在设置页自行开启） |
| `ai_organize` | boolean | `true` | 子开关：AI整理错题 |
| `ai_ocr` | boolean | `true` | 子开关：OCR / 图片识题 |
| `ai_similar` | boolean | `true` | 子开关：相似题推荐 |
| `ai_batch` | boolean | `true` | 子开关：AI批量整理 |
| `ai_text_model` | text | `qwen3.7-plus` | 仅展示用，实际以服务端 `AI_MODEL` 为准 |
| `ai_vision_model` | text | `qwen3.7-plus` | 仅展示用，实际以服务端 `VISION_MODEL` 为准 |

> 开关存数据库 → 刷新、重新登录、换设备后由 `/api/ai/status` 读取，天然一致。
> **服务端以数据库为准**，前端隐藏按钮只是体验层；即使有人直接用 curl 打 `/api/ai/*`，`lib/ai/guard.ts` 也会在发起任何外部请求之前返回 `403 AI功能已关闭`。

完整建表语句、索引、RLS 策略、Storage 策略与触发器见 `supabase/schema.sql`。

## 四、技术方案

### 4.1 架构

```
浏览器(手机/电脑)
  ├─ Next.js 14 App Router + React + Tailwind CSS
  ├─ Tiptap 富文本 / KaTeX 公式 / Canvas 图片压缩 / Service Worker(PWA)
  │
  ├─ 直接读写 Supabase（受 RLS 约束，带登录态）
  │     Postgres + Auth + Storage(mistake-images 私有桶)
  │
  └─ 只调用本站 /api/ai/*  ← 服务端路由（Node runtime）
         ├─ ① auth：校验登录
         ├─ ② ai-guard：查 user_settings 总/子开关 + 环境变量是否配置
         ├─ ③ 限流 / 输入长度 / 超时 / 缓存命中检查
         └─ ④ Coding Plan Chat/Completions（Key 仅服务端可见）
                https://coding.dashscope.aliyuncs.com/v1/chat/completions
```

### 4.2 技术选型与理由

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | Next.js 14 App Router + TypeScript | 一个项目同时承载页面与服务端 API，Vercel 一键部署，类型完整 |
| 样式 | Tailwind CSS | 响应式快，`md:`/`lg:` 断点直接适配手机与电脑 |
| 编辑器 | Tiptap（StarterKit + Image + Table + Link + Placeholder） | 基于 ProseMirror，输出 HTML 便于存库与打印 |
| 公式 | KaTeX | 渲染快、无需运行时依赖浏览器字体服务；约定编辑器内用 `$...$` / `$$...$$` 标记，展示层用 `katex.renderToString` 转换 |
| 数据库/登录 | Supabase Postgres + Auth | 免费、自带 RLS，是「每个用户只能看自己数据」的最省事实现 |
| 图片 | Supabase Storage 私有桶 | 前端压缩为 webp/jpeg（最长边 1600px、质量 0.8）后上传，读取用签名 URL，路径首段 = user_id 做 RLS 隔离 |
| AI | 阿里云百炼 **Coding Plan** · OpenAI 兼容 Chat/Completions | 见 4.3 |
| 图表 | 原生 SVG + CSS 网格 | 不引入图表库，减少体积与构建失败概率；热力图用 div 网格 |
| 打印 | CSS `@media print` + `@page A4` | 浏览器「另存为 PDF」即是 PDF 导出，零后端成本 |
| PWA | `manifest.webmanifest` + 自写 `sw.js` | 只做基础离线只读缓存，避免 next-pwa 构建插件带来的兼容问题 |

### 4.3 阿里云百炼 Coding Plan 接入规范（**强约束**）

| 项 | 值 |
| --- | --- |
| 协议 | **OpenAI 兼容 Chat/Completions**，路径 `/chat/completions`；**禁止使用 Responses API** |
| Base URL | `https://coding.dashscope.aliyuncs.com/v1`（`AI_BASE_URL`） |
| 禁用端点 | 任何含 `maas.aliyuncs.com`、`compatible-mode/v1`、`dashscope.aliyuncs.com/compatible-mode` 的地址 |
| Key 格式 | `sk-sp-` 开头，环境变量 `DASHSCOPE_CODING_API_KEY` |
| 禁用 Key | 普通百炼按量计费 `sk-` 开头 Key（不互通，混用会鉴权失败或产生额外按量扣费） |
| 文本模型 | `AI_MODEL` = `qwen3.7-plus`（也可 `qwen3.6-plus` / `glm-5` / `MiniMax-M2.5`） |
| 视觉/OCR 模型 | `VISION_MODEL` / `OCR_MODEL` = `qwen3.7-plus`（也可 `qwen3.6-plus` / `kimi-k2.5`）—— 官方标注支持图片理解 |
| 模型 ID | 区分大小写、无前后空格、必须是精确版本（`qwen3.7-plus` ✅ / `qwen3.7` ❌） |

服务端 `lib/ai/coding-plan.ts` 会在启动时做**配置自检**：Base URL 白名单校验、Key 前缀校验、模型名 trim + 非空校验。配置不合法时 `/api/ai/status` 返回 `configured: false` 与原因，设置页显示「AI未配置」，**不影响任何非 AI 功能**。

**请求体形状**（OpenAI Chat/Completions）：

```json
{
  "model": "qwen3.7-plus",
  "messages": [
    { "role": "system", "content": "你是错题整理助手，只输出 JSON..." },
    { "role": "user", "content": [
        { "type": "text", "text": "请整理以下错题..." },
        { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } }
    ] }
  ],
  "temperature": 0.2,
  "max_tokens": 2000
}
```

响应取 `choices[0].message.content`，用容错解析器剥掉可能的 ```json 代码块后 `JSON.parse`，得到结构化结果：

```ts
interface AiOrganizeResult {
  normalizedStem: string;         // 规范化题干
  knowledgePoints: string[];      // 知识点数组
  cause: string;                  // 错因
  steps: string[];                // 解题步骤数组
  answerPoints: string[];         // 答案要点
  tags: string[];                 // 标签建议
  difficulty: number;             // 难度 1-5
  reviewAdvice: string;           // 复习建议
  similarQuestions: string[];     // 相似题（前端强制标注「AI生成，需核对」）
}
```

### 4.4 AI 开关的服务端强制执行（验收 16、17、19、21）

```ts
// 每个 /api/ai/* 路由的第一行业务代码
const ctx = await requireAi(ctxReq, 'organize'); // 抛 AiGuardError 时直接 return 403
```

`requireAi` 判定顺序（**在发起任何 fetch 之前**）：

1. 未登录 → 401
2. 查 `user_settings.ai_enabled`：`false` → **403 `{ code:'AI_DISABLED', message:'AI功能已关闭' }`**
3. 查对应子开关：`organize/ocr/similar/batch` 为 `false` → 403 `{ code:'AI_CAPABILITY_DISABLED', message:'该功能已关闭' }`
4. 检查服务端 `DASHSCOPE_CODING_API_KEY` / `AI_BASE_URL` / 模型：缺失或不合法 → 503 `{ code:'AI_NOT_CONFIGURED', message:'AI未配置' }`
5. 全部通过 → 返回 `{ userId, supabase, models }`，此后才允许调用 Coding Plan

`GET /api/ai/status` 例外：它只读取开关与配置状态（不检查开关、不调用 AI），供前端渲染与设置页显示，**它本身永远不会触发任何 AI 请求**。

前端 `AiProvider` 拉取 `/api/ai/status`，全站通过 `useAi().can('ocr')` 决定按钮隐藏/置灰；设置页 PATCH `/api/settings` 写库 → 广播刷新 → 所有设备下次请求即生效，**无需重新部署**（验收 21）。

### 4.5 成本与稳定性保护

| 机制 | 实现 |
| --- | --- |
| 输入长度 | 服务端截断并校验：文本 ≤ 8000 字符，图片 base64 ≤ 4 MB，超出 413 |
| 超时 | `AbortController` 30s，超时返回 504 |
| 限流 | 进程内滑动窗口：每用户每分钟 10 次、每天 100 次；超限 429（生产可换 Supabase 表或 Upstash） |
| 缓存 | `ai_jobs.input_hash = sha256(kind + model + prompt + content)`，命中 `status='succeeded'` 直接返回，不再调用 |
| 重试 | `MAX_AI_RETRIES = 1`，仅对 5xx/超时/网络错误重试；4xx 不重试 |
| 批量 | 前端先显示「预计调用 N 次（缓存命中可能更少）」，用户确认后才逐条串行提交，带进度条；总开关关闭时批量按钮不渲染 |
| 用量 | 每次真实调用写 `ai_usage_logs`（模型、token、状态码、quota_units=1）；设置页可看累计 |
| 幂等 | `ai_jobs` 记录 pending/running/succeeded/failed + attempts，避免重复扣费 |

### 4.6 安全设计

- **RLS**：16 张业务表全部 `ENABLE ROW LEVEL SECURITY`，`to authenticated`，`USING (auth.uid() = user_id)` + `WITH CHECK (auth.uid() = user_id)`。子表同样带 `user_id` 冗余列，策略统一，避免漏配。
- **Storage**：私有桶，`storage.foldername(name)[1] = auth.uid()::text` 四策略（select/insert/update/delete）。图片读取走签名 URL（默认 1 小时）。
- **分享**：不开放 anon RLS。`/api/share/[token]` 用 `SUPABASE_SERVICE_ROLE_KEY`（**仅服务端、绝不进 `NEXT_PUBLIC_`**），校验 `expires_at > now()`、`revoked = false`，并只 select 白名单字段，剔除 `analysis`（可选）、`ai_result`、用户身份、复习备注等隐私字段。
- **密钥**：`DASHSCOPE_CODING_API_KEY`、`SUPABASE_SERVICE_ROLE_KEY` 只在服务端 `process.env` 读取；任何 `NEXT_PUBLIC_` 变量都不含密钥；日志只打错误码与模型名，不打 Key。
- **输入校验**：所有 API 用 zod 校验；SQL 全部参数化（Supabase JS SDK）；富文本在服务端用白名单清洗后再存（前端展示用 `sanitizeHtml`）。
- **敏感操作**：删除、清空回收站、注销账号统一 `ConfirmDialog` 二次确认（输入确认词）。
- **PWA**：离线禁写，避免覆盖云端。
