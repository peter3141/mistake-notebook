## 第 1 步 · 数据模型与迁移 SQL

完整原文：`supabase/migration-textbooks.sql`（幂等，整份粘贴进 SQL Editor 执行，可重复跑，不删改既有数据）。

### 新增 6 张表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `textbooks` | `id, user_id, subject_id→subjects(id), name, publisher, edition, grade, volume, cover_path, note, deleted_at, created_at, updated_at` | 课本；封面只存 Storage 路径 |
| `textbook_chapters` | `id, user_id, textbook_id, parent_id, level(1\|2), chapter_no, title, page_range, summary, sort_order, deleted_at, created_at` | 严格两级：章→节；`summary` 是 AI 出题的可信材料 |
| `chapter_knowledge_points` | `id, user_id, chapter_id, knowledge_point, weight, created_at, unique(chapter_id, knowledge_point)` | 章节↔知识点，权重用于抽题排序 |
| `chapter_mistakes` | `id, user_id, chapter_id→chapters(id), mistake_id→mistakes(id), created_at, unique(...)` | 章节↔错题直接映射 |
| `textbook_materials` | `id, user_id, chapter_id, textbook_id, material_type(catalog\|text\|example\|image\|pdf), storage_path, mime_type, size_bytes, ocr_text, file_name, deleted_at, created_at` | **只存路径，无 Base64 / 二进制列** |
| `textbook_quiz_templates` | `id, user_id, name, config jsonb, created_at, unique(user_id, name)` | 组卷配置一键复用（第 2 段四.5） |

另加：`user_settings.ai_textbook_quiz boolean not null default false`；`ai_jobs.kind` 追加 `textbook_quiz`；`trash_items.entity_type` 追加 `textbook/chapter/material`。

### RLS 策略（原文）

```sql
do $$
declare t text;
begin
  foreach t in array array[
    'textbooks','textbook_chapters','chapter_knowledge_points',
    'chapter_mistakes','textbook_materials','textbook_quiz_templates'
  ] loop
    execute format('alter table public.%I enable row level security', t);
    execute format('drop policy if exists "own_rows" on public.%I', t);
    execute format(
      'create policy "own_rows" on public.%I for all to authenticated using (auth.uid() = user_id) with check (auth.uid() = user_id)',
      t
    );
  end loop;
end $$;
```

### ★ 本轮补上的第 1 个缺口：显式授权

`schema.sql` 里 PART I/II/III/IV 的 `grant` 只在建库那一次执行，**覆盖不到后来新建的 6 张表**。建项目时若没勾 `Automatically expose new tables`，前端会报 `42501 permission denied for table textbooks`。这与之前 v4 修 IV.10b 是同一个坑，本轮在迁移末尾补：

```sql
grant usage on schema public to authenticated, service_role;
grant all on all tables in schema public to authenticated, service_role;
grant all on all sequences in schema public to authenticated, service_role;
grant execute on function public.restore_trash_item(text, uuid) to authenticated;
grant execute on function public.purge_trash_item(text, uuid) to authenticated;
grant execute on function public.purge_expired_trash() to authenticated;
grant execute on function public.delete_my_data() to authenticated;
```

只给 `authenticated` / `service_role`，**不开放 `anon`**；6 张表已有 RLS + `own_rows` 兜底。

### ★ 本轮补上的第 2、3 个缺口

- `update storage.buckets set allowed_mime_types ...` 原来是一条裸 DDL。`storage.buckets` 属 `supabase_storage_admin`，SQL Editor 的 `postgres` 角色可能报 `42501 must be owner`（**用户上次踩过 `comment on table storage.objects` 的同类坑**），一旦报错，后面的回收站扩展/RPC/授权全部不执行。现改成 `do $$ ... exception when insufficient_privilege or undefined_column then raise notice ... end $$`，失败只提示、不中断整份脚本；文档给出 Storage 控制台手动加 `application/pdf` 的兜底。
- 修自检 SQL 的运算符优先级（原来 `where schemaname='public' and A or B` 会让 `schemaname` 条件对 `or` 后半失效），补括号；并新增四合一验收语句，预期 **`6 | 6 | 1 | 1`**（表数 / RLS / 授权 / AI 子开关）。

### 回收站（复用 v2 统一模式）

`sync_trash_item` / `remove_trash_item` 触发器登记 3 类实体；`restore_trash_item` 恢复课本会连带恢复章节与材料；`purge_expired_trash` 纳入新表并按 `deleted_at < now() - interval '30 days'` 清理；`delete_my_data()` 追加清理课本模块。

> 已核对 `schema.sql` 中 4 个原函数签名（`restore_trash_item(text,uuid)→void`、`purge_trash_item(text,uuid)→void`、`purge_expired_trash()→integer`、`delete_my_data()→void`）与迁移里的 `create or replace` **完全一致**，不会因返回类型/参数名冲突导致迁移失败；`trash_items` 的匿名 check 约束自动名正是 `trash_items_entity_type_check`，`drop constraint if exists` 能命中。

## 第 3 步 · 组卷页模式切换、按章节抽题、AI 补充出题

`app/(main)/review/random/page.tsx` 保留原「按条件随机组卷」，新增模式 `random | textbook`；结果在同一页内联渲染，表头已有「**来源章节**」列。

抽题三级优先级（`lib/textbooks.ts:384-455` `drawByChapters`）：

1. `chapter_mistakes` 直接关联的错题 → `matchType: 'direct'`；
2. `chapter_knowledge_points` 的 `knowledge_point` 命中错题的 `knowledge_points[]` 或标签名 → `matchType: 'knowledge'`，按 `weight` 排序；
3. 不足时 `shortfall` → 页面提示「该章节错题不足 N 道，是否用 AI 基于你上传的课本材料补充生成？」，**仅 `shortfall > 0 && ai.can('textbook_quiz') && 目标章节有材料 && 非 loading` 时按钮才可点**。

`drawByChapters` 函数体内**没有任何 `/api/ai/` 调用**（静态校验已断言），所以关闭 AI 后按课本抽真实错题完全不受影响。

AI 结果流程：候选预览 → 逐题勾选确认 / 编辑 / 删除 / 单题重新生成 → `confirmAiCandidates()` 才加入本卷，`includeInPrint: false`。`sendPrint()` 只把 `kind === 'ai' && includeInPrint` 的题用 `aiQuestionToMistake()` 临时适配成打印形状（仅存在于 sessionStorage / 内存），**不写 `mistakes` 表**。打印仍走 `/print`，学生版/答案版/复习版模板不变。配置模板存 `textbook_quiz_templates`。

设置页 `app/(main)/settings/page.tsx:137-146` 显示「课本AI出题：**AI未配置 / 已关闭 / 已开启**」三态；`CAPS` 含 `ai_textbook_quiz`，默认关闭，经 `/api/settings` upsert 到云端 `user_settings`，跨设备同步。

## 第 4 步 · `/api/ai/textbook-quiz` 服务端路由与提示词

`app/api/ai/textbook-quiz/route.ts`，四重门禁**全部发生在 `callCodingPlan()` 之前**（静态校验断言了 `requireAi` 与 `INSUFFICIENT_MATERIAL` 的索引都小于 `callCodingPlan`）：

| # | 门禁 | 不满足时 |
| --- | --- | --- |
| ① | AI 总开关 `ai_enabled` | `403 AI_DISABLED`「AI功能已关闭」 |
| ② | 子开关 `ai_textbook_quiz` | `403 AI_CAPABILITY_DISABLED` |
| ③ | `DASHSCOPE_CODING_API_KEY` + `AI_BASE_URL` | `503 AI_NOT_CONFIGURED` |
| ④ | 该章节有材料 OCR 文字或章节摘要（合计 ≥20 字） | `422 INSUFFICIENT_MATERIAL` + 中文原因 + `questions: []` |

门禁 ④ **从数据库里按 `user_id` 重新读** `textbook_chapters` 与 `textbook_materials`，**不信任请求体的 `materialText`**（防伪造材料绕过门禁）。请求体仍按约定携带科目、课本、章节标题、摘要/OCR 片段、题量、难度、题型偏好。

提示词原文（`lib/ai/quiz-prompts.ts:11-37`）：

```
你是「课本同步练习」出题助手。你【没有联网能力】，也不能访问任何课本数据库。
你唯一可以使用的依据是用户消息里【用户提供的课本材料】。
铁律：
1. 仅基于以下课本材料出题，不得引入材料之外的内容；不得凭记忆引用其他版本…
2. 如果材料不足以出满要求的题量，或材料只有目录/标题而没有具体概念、定义、公式、例题，
   必须返回 {"insufficient":true,"reason":"具体说明缺什么材料"}，不要编造任何题目。
3. 题干、选项、答案、解析里的每个知识点与数据都必须能在材料里找到依据…
4. 每题都要给 confidence_note…
5. 只输出一个 JSON 对象…
```

返回结构化 JSON：`stem / options / answer / analysis / chapter / difficulty / confidence_note`，材料不足返回 `insufficient + reason`；`parseQuizResult` 对不合法结构会返回「材料不足」而不是放行编题。限流 429 / 超时 / 上游 401/403/404 / 网络错误统一走 `aiErrorResponse` 给中文提示并脱敏 key，**不白屏、不静默降级成编题**。`ai_jobs` 按 `input_hash` 缓存，`ai_usage_logs` 记账。

## 附：4 个必答问题

**1. AI 是否能真实联网搜索课本？如果不能，本功能实际靠什么数据出题？**
不能。Coding Plan 只有 Chat/Completions，没有联网/检索能力，代码里也没有任何搜索课本的实现。出题只靠两类真实数据：① 用户上传/手动录入的课本目录、章节内容摘要、正文/例题片段与 OCR 文字（`textbook_materials`）；② 用户维护的 `chapter_mistakes` / `chapter_knowledge_points` 章节映射。按课本组卷抽的是**错题库里的真实错题**，AI 只在材料充足且开关全开时把用户材料改写成练习题，且必须标注「AI生成，需核对，可能偏离课本」。

**2. 用户没上传课本材料时，AI 补充出题按钮是什么状态？**
**置灰不可点**（前提还得是 `shortfall > 0` 且 AI 开关全开）。页面会显示「所选章节还没有课本材料或章节摘要，AI 补充出题已置灰」，目标章节下拉标「（无材料）」、徽章「课本材料：未上传」。即使绕过前端直接 POST，服务端也会在读 DB 材料后返回 `422 INSUFFICIENT_MATERIAL` 与中文原因，`questions: []`，**不编题、不产生上游调用**。

**3. AI 生成题会不会进入错题库或默认打印？**
都不会。AI 题只存在于内存与 `sessionStorage`，`includeInPrint` 初值 `false`，`sendPrint()` 只挑用户手动勾选过的题；`aiQuestionToMistake()` 仅临时适配打印形状，不执行任何 `mistakes` 写入；`drawByChapters()` 只查 `mistakes` 与映射表，AI 题不参与后续随机抽题。当前版本**也没有**「收录为错题」入口，所以是永久不进错题库。

**4. 关闭 AI 后，按课本抽真实错题还能不能用？**
能，完全不受影响。抽题走 `drawByChapters()`，函数体内没有任何 `/api/ai/` 调用，只依赖 `chapter_mistakes`、`chapter_knowledge_points`、`mistakes` 三张表与 RLS。关闭总开关或 `ai_textbook_quiz` 后，`requireAi('textbook_quiz')` 在任何上游请求之前就抛 `403`，组卷页 AI 按钮置灰/隐藏，零调用零费用；课本管理、章节树、材料上传、模板复用、打印导出全部照常。
